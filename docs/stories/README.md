## What a story is

Each story is a vertical slice: it touches every layer needed to produce an observable outcome, and it ends with something you can show. A story is **not** "write the git layer" or "add the events table" on its own.

Every story carries:

| Field | Meaning |
| --- | --- |
| **As / I want / so that** | The user-visible value. The actor is the operator, the agent, or the maintainer. |
| **Size** | `XS` ≤ 2h · `S` ½–1 day · `M` 1–2 days · `L` 2–4 days. Anything larger was split. |
| **Blocked by** | Story ids that must be closed first. No other ordering is implied. |
| **Spec** | Which spec items the story implements. This is how coverage is audited. |
| **Demo** | The one thing you show when it is done. If you cannot show it, the story is not done. |
| **Acceptance** | Checkboxes, each independently verifiable. Spec numbers are quoted, not paraphrased. |

**Definition of done:** acceptance criteria met, `scripts/verify.sh` extended with at least one case and green, the demo performed, and the spec updated if the story changed a decision.

## Decisions taken while slicing

Fifty-seven decisions were made that the spec does not make. Each has an ADR because each is hard to reverse, surprising to a later reader, and the result of a real trade-off.

- [ADR-0001](../adr/0001-build-session-lifecycle-before-docker.md) — the session lifecycle is built against the stub backend before Docker exists. Consequence: there are two fakes, the in-process stub backend and the in-container fake pi, and they are not the same thing.
- [ADR-0002](../adr/0002-security-guards-before-endpoints.md) — the browser guards and network isolation land before the features they protect.
- [ADR-0003](../adr/0003-verification-checks-as-story-gates.md) — V1–V11 are acceptance gates on stories, plus one closing verification run.
- [ADR-0004](../adr/0004-cargo-workspace-with-one-binary-crate.md) — a Cargo workspace with one binary crate. Consequence: `cargo run` from the root needs `-p holosmith`, and `web/` is not a workspace member.
- [ADR-0005](../adr/0005-static-musl-artifacts-proven-without-docker.md) — non-PIE static musl artifacts, proven with `bwrap` and qemu instead of Docker. Consequence: nothing may export `RUSTFLAGS`, and the empty-container run stays open until HS-046.
- [ADR-0006](../adr/0006-one-typed-config-value-loaded-once.md) — one typed `Config`, loaded once from `/etc/holosmith/config.toml` (or `--config`), validated by a three-pass walk that reports every problem at once. Consequence: `config` is settled before `server deploy` writes the file, and `config show` prints unset keys as comments rather than omitting them.
- [ADR-0007](../adr/0007-serve-from-one-assembled-service.md) — serve one assembled axum service from tokio, with the web app embedded and a deadline on shutdown. Consequence: routes are added to a `Routes` and are servable only as an `App`, so a later route cannot skip the middleware HS-005 attaches.
- [ADR-0008](../adr/0008-one-json-error-envelope.md) — every error with a body is `{"code","message"}` and the code is the spec's own name. Consequence: `code` values are effectively an API, and a new code arrives with the story that returns it.
- [ADR-0009](../adr/0009-embedded-forward-only-migrations.md) — the binary opens, asserts and migrates its own database, with numbered SQL embedded at compile time and one transaction per start guarded by SQLite's own write lock. Consequence: the startup banner has eight lines, `serve` owns the data root, and the connection stays out of `AppState` until HS-009 decides how handlers share it.
- [ADR-0010](../adr/0010-browser-facing-guards-are-one-layer.md) — the browser-facing guards are one middleware layer inside `App::new`, so a route added later cannot skip them, and every refusal is the ADR-0008 envelope. Consequence: `GET /api/health` is exempt from all four checks, and no response ever carries a CORS header.
- [ADR-0011](../adr/0011-session-row-id-and-absent-status-check.md) — a session's id is 16 lowercase hex characters generated by SQLite before the insert, and its six states are a Rust enum rather than a `CHECK`. Consequence: no uuid crate, and the state machine HS-012 adds needs no migration.
- [ADR-0012](../adr/0012-create-endpoint-shared-connection-and-cap-refusal.md) — the create endpoint takes the raw body, decides its refusals in one fixed order, and shares `Arc<Mutex<Database>>` with the cap count. Consequence: no `axum::Json` extractor, and validation is shape, not vocabulary, until HS-031 learns pi's real values.
- [ADR-0013](../adr/0013-event-log-single-writer-and-seq-counter.md) — one writer thread assigns every seq from `sessions.last_seq`, commits a batch every 25 ms and broadcasts only what survived. Consequence: the mutex stays and the database actor is deferred; an event a client sees is an event a crash cannot undo.
- [ADR-0014](../adr/0014-event-stream-replay-lag-and-open-stream-registry.md) — a stream subscribes before it replays, drops a lagging subscriber with a `stream_lagged` event, and keeps a per-session count of open streams. Consequence: `futures-core` becomes a direct dependency, and the heartbeat is axum's `KeepAlive` rather than a second writer on the connection.
- [ADR-0015](../adr/0015-one-backend-trait-per-step-and-a-background-provisioner.md) — the backend trait is one method per provisioning step, the provisioner is one spawned task per accepted session, and progress is five `session.status` events. Consequence: `AppState` carries the backend, `backend` becomes a config key with `--backend` overriding it, and the Docker backend refuses every operation until HS-024.
- [ADR-0016](../adr/0016-one-transition-table-and-one-function-that-applies-it.md) — the session states and their triggers are one data table, applied by one function that persists the change and then emits `session.status` with `from`/`to`. Consequence: no production code writes a state anywhere else, a source-level guard proves it, and a step beginning is a payload with `from == to` rather than a table row.
- [ADR-0017](../adr/0017-the-sessions-list-and-one-stream-per-visible-session.md) — `GET /api/sessions` answers `{"sessions":[…],"network_default":…}`, one `EventSource` per visible live session patches a row in place, and the page holds nothing but the DOM. Consequence: the create form's checkbox default needs no second endpoint, HS-061's paging has an object to grow into, and a retry repeats its `Idempotency-Key` while the next create does not.
- [ADR-0018](../adr/0018-the-transcript-contract-and-one-block-per-message.md) — four event kinds (`message.delta` with `message_id`/`kind`/`text`, `message.snapshot`, `turn.start`, `turn.end`) are pinned before their producer exists; a transcript block is keyed by message id and a delta is one appended text node, never a re-read; and the renderer's rules are tested with node's own runner over synthetic frames. Consequence: HS-015 emits these kinds and adds three of its own (ADR-0019), an unknown kind is dropped rather than refused, and the DOM half of the screen stays unverified from source until a browser or the producer exists.
- [ADR-0019](../adr/0019-the-turn-runner-and-the-backends-events.md) — the prompt's transition is the handler's and the way out of `running` is the turn runner's, a backend emits its turn's events but can never move a state, and a prompt is refused with one `409 session_<state>` code per state rather than an umbrella code. Consequence: `SessionBackend::start_turn` takes the event writer, the stub scripts a turn with `msg-<n>`/`tool-<n>` ids, `message.end`, `tool.start` and `tool.end` are pinned before HS-033/HS-034 fill them in, and `last_active_at` moves through one new repository method (`touch`).
- [ADR-0020](../adr/0020-the-abort-ladder-and-how-a-turn-is-cancelled.md) — abort climbs two rungs (clear the queue and ask the agent, then kill the container after `abort_grace`), the backend reports how its turn ended (`TurnEnd`) while the runner still chooses the table row, and the ladder is one routine whose reason is a parameter. Consequence: `running` has two owners on a forced stop and the table decides between them, the resume after rung 2 goes through the provisioner, and the refusal family gains `session_idle`.
- [ADR-0021](../adr/0021-a-steers-frame-and-what-was-delivered.md) — a steer is recorded as a `turn.steer` frame with no message id, the agent is asked before the record is written so the log holds what was delivered, and a `409 session_idle` keeps the guidance in the box rather than resending it. Consequence: a steer block is created per frame (the one exception to ADR-0018's "a message id keys a block"), and the composer's third button is wired.
- [ADR-0022](../adr/0022-the-way-back-and-no-stop-endpoint.md) — resume is the only way back, the cap is checked before its transition so a refused resume never strands a row in `starting`, and `SessionBackend::resume` is still uncalled because the provisioner is what brings a session back. Consequence: nothing in the API produces `stopped` until the eviction, idle-stop and drain stories do, and the page resumes once and retries the refused request once.
- [ADR-0023](../adr/0023-the-delete-flow.md) — the delete flow's snapshot is the request's (so a failed one can answer 409 `unsaved_work` and leave the row untouched) and the removal is a task's; the turn is ended first by the ladder's `end_turn`, which stops and does not resume; the event log goes with the row, which makes the writer drop an event whose session has gone instead of refusing its batch. Consequence: a delete of a running session can take up to `abort_grace` to answer, and a backend failure leaves the row `deleting` for a repeated request to retry.
- [ADR-0024](../adr/0024-the-cap-and-eviction.md) — the create evicts the least recently active `idle` session outside its own lock scope, because a state change is `Transitioner::apply`'s and that takes the lock itself; only `idle` is a candidate, and the victim is `last_active_at`'s. Consequence: a create at the cap with nothing idle still refuses with `cap_reached`, a resume on a full machine still refuses rather than evicting, and the page says in one word that nothing was deleted.
- [ADR-0025](../adr/0025-the-idle-stop-sweeper.md) — the idle stop is a sweeper task on a fixed five-second tick, its candidates are one repository read of every `idle` row past `idle_stop_min`, each stop is one `apply` and one spawned best-effort `stop`, and `idle_stop_min = 0` turns the task off. Consequence: the tick is not a config key (so the gate waits a real minute), the reason vocabulary gains `idle_stop`, and the page says what happened in that reason's own words rather than the cap's.
- [ADR-0026](../adr/0026-the-turn-timeout.md) — the turn timeout is the turn runner's own deadline rather than a sweeper, because the row keeps no per-turn timestamp (`last_active_at` moves on a steer, so a watcher would let a steered turn run for ever) and rung 1 needs the turn future alive to answer; both endings record `turn_timeout`, the runner's `running → idle` when the agent answers and the ladder's `running → stopped` when it does not. Consequence: no new column, no migration, and `turn_timeout_min = 0` builds no timer at all — so the gate can only prove that a short turn is not ended early, not that the deadline fires.
- [ADR-0027](../adr/0027-the-token-budget.md) — the token budget counts a column the event writer adds to inside the transaction that assigns the seq, because the backend emits `message.end` and the runner never sees the frame; the ceiling itself is the turn runner's, polled every hundred milliseconds next to ADR-0026's deadline and climbing the same ladder, and the first policy to fire owns the reason. Consequence: the events repository parses exactly one kind's payload, a turn that settles over its ceiling records the reason instead of being aborted, and a backend that reports no usage cannot trip anything — the screen says so instead.
- [ADR-0028](../adr/0028-the-docker-preflight.md) — the Docker preflight is a startup refusal rather than a per-request check, because item 10 §5 puts the same check in the unit file as `ExecStartPre`; its failures are `Complaint` values (a check and one sentence naming the fix) reported all at once, so `serve`, the Docker backend and HS-045's `doctor` print the same words. Consequence: no new dependency (`df -Pk` and `git --version` are subprocesses, `_ping` is four lines over a std socket), and a check that cannot run — an `ssh://` daemon, a missing `git` — is a complaint rather than a silent pass.
- [ADR-0029](../adr/0029-the-worktree-is-made-by-the-backend-and-recorded-by-the-provisioner.md) — the worktree's five host commands live in one `src/worktree.rs` value that the Docker backend runs off the runtime's worker; the backend answers `Provisioned::Worktree { path, base_commit }` and the **provisioner** writes the row, because a backend may not write one (ADR-0019); `ensure` is idempotent (create or adopt) so a resume re-provisions a worktree that is still there, and the row's `base_commit` wins over the branch's head so `ahead` keeps its starting point. Consequence: no schema change and no `ahead` column — the number is a function on the worktree and `GET /changes` (HS-061) is what publishes it — a step that only **adopted** a worktree is not undone when a later step fails (those commits are the agent's) while a delete removes it like any other, and teardown treats a missing worktree, branch or project repository as success, so a delete cannot wedge on ADR-0023's `deleting` row.
- [ADR-0030](../adr/0030-the-projects-refusals-are-the-creates-422.md) — a project the machine must not mount is refused by the **create** with its own `422` (`git_not_directory`, `submodules_present`, `worktree_config_enabled`) and one sentence, because the provisioner has no request to answer and the spec says "refused with 422 at session creation"; the rules are `worktree::refuse`'s (filesystem reads plus one `git config --type=bool`), the question is `Backends::refuse`'s (the stub mounts no repository, so it refuses nothing), and the read runs on `spawn_blocking`. Consequence: a project the machine does not hold is refused rather than accepted into an `error` row (HS-025's behaviour, changed here on purpose), the refusal is raised after the idempotency lookup and before the cap so a retry still answers its row and a refused create never evicts, the **resume** asks the same question (so a project that became unsafe cannot be reopened), the `extensions.worktreeConfig` read is `--local` (a global key must not refuse every project), a repository git cannot read answers `500 internal` with git's words logged, and the create form prints the sentence alone for those three codes.
- [ADR-0031](../adr/0031-coalescing-in-the-writers-batch.md) — event coalescing is the writer's, in a pure `coalesce(batch)` between `collect` and `commit`, because that batch is spec item 15's "inside each 25 ms commit" and ADR-0013's one place a seq is assigned; a delta merges into the row before it only when the session, the `message.delta` kind, the message id and the delta's own `text`/`thinking` all match, and anything between two deltas ends the run. Consequence: the writer reads a second payload (the repository still parses exactly one, ADR-0027 — a count ADR-0032 widens to three), a payload that is not the pinned shape is passed through untouched and ends its run, adjacent rows of one message and kind may still sit together across commits, and the merge itself can only be shown by a burst — `tests/events.rs` (5,000 → three rows) and `tests/turns.rs` (seven → three) — because the gate's stub paces eight commit windows apart.
- [ADR-0032](../adr/0032-compaction-is-a-per-session-pass-inside-the-lock.md) — compaction is a background task whose per-session pass runs **inside the database mutex the transitioner also takes**, so a turn either started before it (the row says `running` and the pass skips it) or starts after it; the 24-hour window is the spec's fixed number and not a config key (`Compactor::with_window` is how a test chooses one), the fold is one transaction per session bounded by `MESSAGES_PER_PASS` after the already-folded filter, the snapshot takes the highest removed seq and never moves `sessions.last_seq`, and nothing is broadcast. Consequence: `message.end`, tool frames and turn boundaries are never removed, a delta whose payload is not the pinned shape stops the whole session for that pass rather than losing text, and the only way to show the window from the shipped artifact is to stop it, age the log and start it again — which is `case_compaction` and the story's own demo.
- [ADR-0033](../adr/0033-history-truncation-and-pagination.md) — a stream opened with no `Last-Event-ID` is replayed from the **lowest seq of the `history_window`-th most recent message**, found by a backwards scan over the message-bearing kinds so a block is always whole; the cut is computed in the stream's read step and only for a client with no resume point, and it is announced by a `history.truncated` frame carrying `{before_seq, turns_before}` and **no** SSE `id` (it is not a stored event). Consequence: the window is a config key (`history_window`, default 50, `0` refused), a page is `seq < before ORDER BY seq DESC LIMIT n` and therefore stable under concurrent writes by construction, `before` is required with a new `422 bad_query`, and the page numbers a turn from `turns_before` rather than from the frames it was not sent — `case_history` and `tests/history.rs` are where the two halves meet.
- [ADR-0034](../adr/0034-the-project-backup-is-one-verified-bundle-per-day.md) — the `project_backup` bundle is **one git bundle per project per calendar day (UTC)**, named `<data>/backups/<project>-<YYYY-MM-DD>.bundle`, so "has today's been taken" is a `stat` and the name is also the retention rule's sort key; it is written aside, checked with `git bundle verify` and only then renamed into place, so a file under the final name is always one git can read, and the last seven days per project are kept. Consequence: the **create** takes it — awaited, after the row exists and before the provisioner is handed the session — because the story says "before the first session of each day", and every failure is one `warn` line that does not block the session, because a broken safety net must not become an outage.
- [ADR-0035](../adr/0035-the-hardened-git-mounts-are-one-value.md) — the hardened `.git` mounts are one value (`container::Mounts`: worktree at `/work`, the repository's `.git`, and `.git/hooks`/`.git/config` stacked on top of it read-only), and **V1 passes as specified** on a real daemon, so the spec's narrower fallback is not applied. Consequence: the repository's three mounts keep their **host path inside the container**, because a worktree's `.git` *file* holds an absolute `gitdir:` under `<project>/.git/worktrees/<id>` and any other container path would point git at something nothing mounted; `--user` is deliberately not passed (the image's default user must be non-root, and the gate reads `id -u` instead of guessing a uid the deploy step owns); a mount source that is missing or of the wrong kind is refused **before** `docker run`, because Docker creates a missing source as an empty root-owned directory and would mount nothing; and the image became the config key `agent_image` (default `agent-image:<version>`, this machine's `pi-agent:local`).
- [ADR-0036](../adr/0036-hs-028-fills-the-network-step.md) — HS-028 fills the **network** step as well as the container one (a container cannot join a network that does not exist, and spec item 6's run line names `--network agents_<id>`), creates it `--internal` because that *is* the isolation, and leaves the `egress` network, the proxies, the startup self-test and orphan cleanup to HS-036. Consequence: the container runs **detached** with `sleep infinity` as its placeholder command until HS-031 attaches pi's stdio, the limits are three integer keys (`container_cpus` 2, `container_memory_mb` 4096, `container_pids` 512, each refusing `0` because Docker reads zero as *unlimited*), the `docker` CLI is one module that passes `-H` rather than inheriting `DOCKER_HOST`, `Mounts::check` runs before every `docker run` (ADR-0035's measurement), and the flags are asserted by `docker inspect` in `tests/container.rs` while the gate asserts the step *order* and that nothing is left behind.
- [ADR-0037](../adr/0037-a-per-session-start-lock.md) — a container start is `docker rm -f` **then** `docker run`, in one function, because `--rm` removes an exited container only *after* `docker stop` has already returned (measured), and because a container the process lost track of has to be replaceable; the two calls are serialised per session by a `tokio` mutex so two starts cannot interleave into "the container name is already in use". Consequence: `SessionBackend::resume` gets a body at last — network then container, no worktree, because the worktree step's `ensure` is create-or-adopt (ADR-0029) — and `stop` becomes `docker stop --time 10` with the expected-stop flag and the exit classification still HS-030's.
- [ADR-0038](../adr/0038-the-expected-stop-flag-and-the-exit-classifier.md) — the expected-stop flag is a `sessions` column that no client is sent (`Session` is the API's body, and phase 1b may not change the API), written by one `Stopper` that the sweeper, the eviction and the ladder's forced rung all use, and taken with a compare-and-swap because SQLite's `RETURNING` on an `UPDATE` answers the row *after* the write; a clean exit becomes its own table row (`pi_exit`) because item 8's "exits unexpectedly → error" is what item 6 replaces for code 0; and the classifier is a pure function whose `Exits::record` has **no production caller yet** — HS-031's attached stdio is the only thing that can observe an exit in this build, since the container runs detached and `--rm` takes it away a moment after it stops. Consequence: the demo is half-showable (the flag from the artifact, the three outcomes from `tests/exit.rs`), and `session.log` gets its writer.
- [ADR-0039](../adr/0039-the-container-is-the-agent.md) — the container *is* the agent: an attached `docker run -i` whose stdio is pi in RPC mode (so `--detach` and the `sleep infinity` placeholder are gone, and the exit code and stderr HS-030's classifier needed finally have an observer); "ready" is the response that repeats a `get_state` command's id, under a 30-second bound; pi's directory is a **fifth mount at its own host path** rather than the spec's illustrative `/home/agent/.pi/agent` (item 1's host-path identity, and Docker creates a missing *destination* root-owned for an image whose user this build does not choose), seeded once from an embedded template with the row's model and thinking level in pi's own two settings keys and no secrets; project trust is `--approve`, which `get_commands` makes observable; the exit is recorded by the server through a new `supervise` seam, and an exit for a container a newer launch replaced is **not news** (ADR-0038's inherited ordering, closed by keying the flag to the launch generation); and the launch line is built from an allow-list of fields, so nothing in it has to be redacted.
- [ADR-0040](../adr/0040-the-mapping-layer.md) — pi's records become the transcript's frames in one pure module (`src/rpc.rs`), so the committed fixture of a real turn replays through the code a container drives; message ids are minted per process (`msg-<instant>-<n>`) because pi's messages carry none; `text_end`/`thinking_end` content is **not** re-emitted (the deltas already said it, and `message.snapshot` has exactly one producer); `message.end` gains `stop_reason` and `tool_calls` additively; the transcript's turn is the *prompt*, so `pump` writes the boundary pair and pi's per-response `turn_start`/`turn_end` are declined; `agent_settled` is the only record that ends a turn, records this build knows are declined while ones it has never seen are a `warn`; records cross on a bounded channel the reader *waits* on, so a slow commit slows pi instead of losing text; and a removal the server provokes **supersedes** the launch first — in the one removal function, which the container step now calls — so the `docker rm -f` a resume performs cannot classify its own exit as an unexpected death.
- [ADR-0041](../adr/0041-tool-output-is-a-file.md) — a tool call's **output is a file**: `tool_execution_start`/`_end` become `tool.start`/`tool.end` (the provider's `toolcall_*` stay declined, because they are the same call's streamed arguments and mapping both would open two blocks for one call), the payloads gain `status` (`ok`/`error` from pi's `isError`, because pi reports no exit code), `duration_ms` and `output_ref` additively, the whole output goes to `<data>/sessions/<id>/tool/<tool_id>.txt` capped at 5 MiB on a character boundary with one truncation marker line, the frame carries a 2000-character preview, and `GET /api/sessions/{id}/tool-output/{tool_id}` serves the file — with the id checked against an allow-list (`[A-Za-z0-9_-]{1,128}`) *before* anything is joined, so a traversal is impossible by construction rather than by cleaning up, and the row read before any directory is, so a deleted session's leftovers are not reachable. Consequence: the write belongs to `rpc::pump` and not to the mapping (which stays I/O-free, so a fixture still replays without a data root), `session.log` stays stderr-only, and an image in a tool result is named `[image]` in the text today because storing and rendering it is HS-035's.
- [ADR-0042](../adr/0042-what-a-token-count-is.md) — a token count is what the message **cost**, so `message.end`'s `in` is pi's `input` **plus the cache counters** (`cacheRead`, `cacheWrite`) and `out` is `output` (`reasoning` is already inside it — the fixtures prove the arithmetic, and `tests/rpc.rs` asserts `in + out == totalTokens` on every record of every committed turn); a report of **zero is not a report**, so a zero sum emits no `usage` key at all, which makes the screen's "no usage reported" sentence and the disabled ceiling one fact instead of two; the visible warning is the session screen's one sentence, keyed on the log, rather than a per-turn server `warn`; and "against the real backend" is a real turn's records through the production mapping and a real runner over the row they land in, because a container cannot complete a turn until the key proxy exists (HS-039) — the container itself is HS-046's.
- [ADR-0043](../adr/0043-an-image-is-a-file-and-a-dialog-is-cancelled.md) — two records the mapping can finish only with more than a frame, and both are **I/O the pump owns**: an image in a tool result is a file beside the tool's text (`<data>/sessions/<id>/tool/<tool_id>-<block index>.<ext>`, the extension from a four-row type table with a `.bin` fallback, the base64 decoded by the store with the cap checked from the encoded length *before* anything is allocated), named by `tool.end`'s `images: [{index, mime, output_ref}]` additively and served by `GET /api/sessions/{id}/tool-image/{tool_id}/{index}` with the type the *file* has — never a type the request asks for; and an extension's dialog (`select`, `confirm`, `input`, `editor`) is **cancelled**, because pi blocks the run until the client answers, with the `extension_ui_response` written by the pump through a new `Agent::respond` **before** the frame, while the fire-and-forget methods stay declined and an unknown method is the `warn`. Consequence: a fifth kind, `turn.error` with `{reason, method}` and no message id (a steer's shape), because the acceptance asks for an `error` event and the contract had no error kind.
- [ADR-0044](../adr/0044-the-isolation-is-measured-at-startup.md) — the network isolation is **measured at every boot** rather than asserted: a probe container from `agent_image` on a temporary internal network tries the internet (`1.1.1.1:443`) and the host (the default bridge's gateway on 2375), and **a refused connection counts as reached** because a reset proves the host answered — measured both ways on this machine, so "passed" means something. Three outcomes and only one refuses: `Passed` is a `debug` line, `Unknown` (no image, a daemon that cannot create networks) is one `warn` and the boot continues — "we could not measure" is not "we measured a leak", and a machine whose image is not built yet must still serve the UI that says so — and `Failed` refuses the boot through `preflight`'s own complaint list. The temporary network is always removed, and the machine's own `egress` network (not internal, for the proxies of HS-037/039) is created at startup with a `warn` rather than a refusal for the same reason. Owed: orphaned `agents_*` cleanup, which the acceptance names HS-044 for.
- [ADR-0045](../adr/0045-the-egress-proxy.md) — the egress proxy is a **second mode of this binary** (`holosmith proxy egress`) and its container runs *this* artifact, mounted read-only at its own host path, so the image needs no build of its own until HS-048 ships `holosmith-proxy`; the allow-list is an **exact domain** because `config` already refuses a wildcard and a suffix match would be that wildcard under another name; the **address** decides before the connection is made and *every* answer a name has is checked (loopback, link-local, RFC 1918, 100.64.0.0/10 and their IPv6 spellings, with an IPv4-mapped address judged as the IPv4 address it carries), so `localhost` is refused **even when it is on the list** — which is the gate's case, not only a unit test; `CONNECT` to 443 only with 405 for another method and 403 for another port; attribution is the **proxy username**, which is why the container's `HTTPS_PROXY` is `http://<session-id>@egress-proxy:3128` and `egress-proxy` is a network alias rather than the container's name; the attach is the **network step's** and runs only when the session's `network` flag is set (the UI and the off-case probe are HS-038's), a teardown detaches before `network rm` because Docker refuses a network with an active endpoint, and every proxy failure is a `warn` rather than a refusal because an unreachable proxy fails a download, not a session.
- [ADR-0046](../adr/0046-the-checkbox-is-topology.md) — the Internet-access checkbox is **topology**: the container carries the same `HTTPS_PROXY` either way, so what an operator is told about it may not name an environment variable, and the phrase the session screen shows (`networkText`) is a tested rule rather than a ternary in `main.ts` — the rendered bytes are HS-013's, because this phase forbids a UI change. The **off case is measured, not assumed**: the self-test's probe gains `egress-proxy:3128` — the **alias**, never the container name, because `hs_egress` resolves on the `egress` network only and a probe asking for it would pass on every machine, joined or not — so a proxy that answers where nothing should leave is a *reached* target by ADR-0044's rule and the boot refuses with its own sentence instead of the bridge one. A name that does not resolve is the measurement because a closed port answers `refused`, which ADR-0044 counts as reached; and the **key proxy is deliberately absent** from the list until HS-039, because a target nothing answers would turn "only the key proxy" into a claim. And the probe runs **twice on that network** — bare, then with the proxy joined for the alias alone — because a silence is only evidence if the alias answers the moment something is attached; the second run is a `debug`/`warn` line and never a verdict, since a proxy that will not join fails a download rather than a session. V6 is `case_internet_toggle`: two real sessions differing only in the body's `network`, two questions asked on each network from a probe container (the internet directly, unreachable in **both** cases; the alias) and a third read off the containers with `docker inspect` (every environment variable identical once each session's id is normalised), then the choice as the network's **endpoint count** after the proxy is **detached** and the container killed and resumed — 1 for the off session and 2 for the on one, which is a rejoin rather than an inheritance and a wrong flag's signature.
- [ADR-0047](../adr/0047-expand-contract-and-the-previous-schema.md) — expand/contract turned out to have two halves and the repository had one: `schema::contract_violations` (ADR-0009) refuses an **unmarked** destructive statement in a migration — immediately, in `cargo test`, matched on words so `renamed_at` and `decontract_legacy` are not false positives — and nothing compared a release with the one before it, because a single file cannot see "something an earlier release still uses". So the second half is a **fact**: `docs/schema/previous.sql`, a real dump of the previous release's schema, kept **out of `migrations/`** (that directory is embedded and byte-grepped into the artifact) and compared by **SQLite itself** (`sqlite_master` + `pragma_table_info`, not a second SQL grammar in this repository), as a **subset** — adding is the point — with two non-vacuity guards and a comparison function whose own tests drop, rename and add. **Measured both ways**: a `_contract_`-marked `DROP COLUMN` passes the scanner and fails the subset test with the instruction; the same file unmarked fails the scanner. The snapshot moves at **release time** (`scripts/schema-snapshot.sh`), so its diff is the record of what a release gave up — the machine can enforce *deliberate*, never *temporal*. And "a newer database" is split by moment: `schema::verdict` is one function with one sentence, `serve` continues (a rollback must not need a restore) and `doctor` (HS-045) refuses, with a gate case that boots the artifact over schema 99 and asserts the banner's recorded number, the warn's two versions and a 200 from `/api/health`.
- [ADR-0048](../adr/0048-the-key-proxy-is-a-second-plaintext-proxy.md) — the credential path is a **second plaintext proxy**: `keys.toml` (0600) holds both the real provider keys and the per-session dummy keys, because `hs_key` has no database and must answer "is this dummy valid?" from the one file that minted it; writes are temp-file + rename so a proxy never reads half a key; `key set` reads stdin only, so a key is never in `argv`; a request's first path segment selects a fixed **provider table** (host, base path and auth header), never a request-controlled host or port — ADR-0045’s exact-list rule on the other proxy; the artifact is static, so TLS is `openssl s_client` from the agent image and a missing binary is a 502; the request is held up to 32 MiB for its `Content-Length`, while the response is copied chunk by chunk so an SSE body streams; the network step joins `hs_key` to **every** session network under the `key-proxy` alias (the provider is reachable with the checkbox either way), while `hs_egress` stays conditional; and the self-test gains the inverse pair — join `hs_key`, require `key-proxy:8080` to answer — which is a `warn`, never a boot verdict.
- [ADR-0049](../adr/0049-the-wip-snapshot-is-a-temporary-index-and-a-ref.md) — the WIP snapshot is spec item 9's **temporary index** made one module: `GIT_INDEX_FILE` on every index-touching command (so `git add -A` never reaches the session's own index, and `read-tree HEAD` stages a deletion as a deletion), `commit-tree` with the identity passed by `-c`, and `update-ref` to `refs/holosmith/wip/<id>`; a tree equal to `HEAD` **removes** the ref rather than writing a second name for nothing (HS-043's keep-rule is "differs from the branch"); the turn runner takes one on every `agent_settled`, `Stopper` takes one before every stop, and the delete flow keeps its `409 unsaved_work`, with a failure reported rather than swallowed; `holosmith container snapshot` is the same function with `/work` and `HS_SESSION_ID`.
- [ADR-0050](../adr/0050-the-key-proxys-request-is-its-bytes.md) — the key proxy's **request is its bytes** and its **store is a directory**: `upstream` returns head *and* body (a `Content-Length` without bytes is a request the provider waits out and closes, which is what every model call did until HS-040 measured it), and `hs_key` mounts `<data>/secrets` rather than `keys.toml` itself, because the store is written by temp-file-and-rename and a file bind mount pins the inode — the proxy would keep reading the store from before the first create and answer `bad-key` for every session; a provider row is one (host, path, auth) triple and therefore one API shape, so `opencode-go`'s anthropic models are `/inference/go/anthropic` with `x-api-key`; and V5's measured precedence is `auth.json` > `models.json` `apiKey` > the provider env var, so the seeded pi-home and the container environment stay the only two sources removed.
- [ADR-0051](../adr/0051-the-preview-listener-is-a-byte-tunnel.md) — the preview listener is a **byte tunnel** to the container's own address, because V7 was measured passing (the host reaches a container on an `--internal` network, while the container still reaches neither the internet nor the host) and a forwarded HTTP exchange through `axum` would need hyper's `client` feature (`want` in `Cargo.lock`) and would have to re-frame chunked bodies; the dev-server port is one config key (`preview_upstream_port`, default 3000) because the image declares no `EXPOSE` to read, the prefix is stripped and **nothing else is rewritten**, an upgrade's `Origin` (present and equal to `preview_origin`) is the only check item 3 asks for, a plain `GET` with a foreign origin and every method are proxied, a preview bind that fails is one `warn` with the banner saying so, and `preview_origin` is `GET /api/health`'s fifth key because that is where the page already looks.
- [ADR-0052](../adr/0052-what-a-delete-keeps.md) — what a delete keeps is `worktree.rs`'s rule, not the `Deleter`'s: `Worktree::retained(base_commit, targets)` answers `Retained::{Known { branch, wip }, Unknown}` and `remove` is told what **not** to delete, because that module already holds every host git command a session makes (ADR-0029) and `tests/worktree.rs` can then prove the rule on a real repository with no daemon, backend or request. "Commits beyond the base" is `ahead`'s with the row's `base_commit` (no base, or an unreadable repository, keeps — "cannot tell" must never mean "delete"); "not merged into a target" is one `git merge-base --is-ancestor` per **existing** `[merge] targets` name, a target this repository does not have is not a merge (the default names both `main` and `master`) and a repository with no target at all keeps the branch; the wip ref "differs from the branch" is a **tree** comparison (ADR-0049's reading, which is why a snapshot whose tree equals `HEAD` removes it), and since nothing deletes that ref the rule only decides whether the answer **names** it. The 202 gains one additive key, `kept` (`branch`, `wip`, `recovery`), by flattening the row, so `Session`'s fifteen columns stay the body and no other route changes; the command `git branch rescue refs/holosmith/wip/<id>` is built once and the page shows what the answer carried. The handler computes the answer **after** the snapshot and before the transition and hands the spawned task the same value, `?force=true` forgives only the snapshot, and the UI half — a Delete button with a confirm step, the `409 unsaved_work` path offering the forced delete, and the kept notice — is this story's, because a recovery command nobody can reach does not satisfy it.
- [ADR-0053](../adr/0053-the-startup-reconcile.md) — the startup reconcile is **one pass awaited before the first request is answered**, not a task: a sweep spawned beside a create takes the worktree that create has just made (the story's demo measured it). The row half runs for every backend and the name half only for Docker; `running` becomes `starting` with reason `interrupted` and the re-provision's settle carries it too, so the row rests at `idle · interrupted`; a container is swept unless its row is a `deleting` delete in progress, while a network and a worktree directory go only when **no row** has the id; **never a branch, never a ref** (`git worktree remove --force` plus `remove_dir_all` for an unregistered directory, `Retained::Unknown` keeps the branch); Docker is read through `--format '{{.Names}}'`/`'{{.Name}}'` and a 16-lowercase-hex check rather than its English or its substring filter, every call is bounded, and a second pass leaves the same names and rows — it restarts live sessions again, which is why `doctor` and HS-046 may call it.
- [ADR-0054](../adr/0054-the-doctor-is-the-preflights-list-printed.md) — `doctor` is the **preflight's list printed**, not a second implementation: `preflight::Finding` (check + `Outcome::{Pass,Fail,Unknown}` + the sentence) is the one value per check and `Complaint` is its failing projection, so `serve`'s refusal and `doctor`'s line carry the same string while a pass line comes from the same function's other arm; one `Check` word table, extended rather than duplicated; **only `fail` changes the exit code** — `unknown` is "no verdict about whether `serve` may run here", which is how a machine with no systemd and no `tailscaled` still runs `doctor --quick` (HS-049 is where they become deploy prerequisites, and `tailscale`'s logged-out arm is a real `fail`); **ports are two moments** — free is the pass before a start, the machine's own `/api/health` answering is the pass after one; the database is read with `SQLITE_OPEN_READ_ONLY` through `db::recorded_without_migrating` and refused on `schema::verdict`'s `Newer`, which is ADR-0047's promise kept; and **V2's trial-merge fallback is not implemented** for ADR-0035's reason — the git check refuses below 2.38, so a git without `--write-tree` never reaches the trial, and its `unknown` says so.
- [ADR-0055](../adr/0055-the-verification-table-is-the-record.md) — the spec's **`Result` column is the record** and there is no second document: a cell carries the verdict, the automation that produced it — a `case_*` in `serve_cases`, a `tests/*.rs`, a `scripts/*.sh`, or `docs/build.md`'s by-hand section — and, on a failure, the fallback taken; `case_verification_table` fails the gate when a V1–V10 row still says "not yet run", when a cell carries no verdict, when a cell names an automation the repository does not have, or when V11 stops saying it is deferred to HS-070 (and the eleven-row count keeps a broken read from passing over nothing); **`doctor --full` grows no verification check**, for a per-row reason — V2 already *is* its `merge` finding, V1 would re-spell the mount vector ADR-0035 keeps in one place, V6/V7/V9 need a session a check must not create, V8 is `cargo test`'s fixture replay, V10 is the build, and V3–V5 need a key no gate may hold — so "as many as it can" is recorded rather than widened; and repeatability is one command, because `scripts/verify.sh` now prints one `ok <case>` per case, so the run's log and the table share their vocabulary.
- [ADR-0056](../adr/0056-the-deploy-is-a-list-of-steps-each-a-read-and-an-apply.md) — `server deploy` is a **list of steps, each a state read and an apply**, printed as one line `<n>. <step>: <word>: <sentence>` with exactly five words — `satisfied`, `needs` (a dry run's plan), `changed`, `skipped` and `failed` — because "each checking current state first" and "the second run changes nothing" are one decision; **a `skipped` step is never a pass**, it names the story that owns its body (step 3 is HS-048's, steps 5–6 and step 7 entirely are HS-049's), and the summary says how many steps are still other stories'; step 2 is split the same way — this story creates the four paths the tree already writes (the data directory, `config.toml` from `config::render`, the 0700 secrets directory with its 0600 `keys.toml`, `/run/holosmith`) and the service user and VAPID stay HS-049's, recorded here because `docs/stories/**` is not edited; **`--root DIR` prefixes every path the deploy installs and nothing it reads about the machine**, and it decides privilege — no `--root` means one `sudo install`/`chmod` child per action, `--root` means the same child without `sudo`, and the deploy never reads a uid; `keys.toml` is **never** installed over an existing file (it truncates and would take every stored key); there is **no `--from`** — the resume is the same command with the same absolute `--root`/`--config`, because a second syntax is a second entry point; step 1 is `doctor --quick` with **one** downgraded finding, `ports`, because deploy is the one caller that legitimately re-runs on a machine that is already serving, and `doctor`'s own exit code and two-moments test are untouched; step 4 reads the network and both containers and does **not** reconcile `[egress] allow` (that is the boot's replacement) — and its recipe moved into `proxies.rs` so the boot and the deploy start the same two containers, with a `proxies::Containers` seam so step 4's real `docker run` vector is asserted without a daemon; the exit code is 1 iff a step failed, so a run whose remaining steps are later stories' ends 0 with an `incomplete` line rather than pretending.
- [ADR-0057](../adr/0057-the-two-images-are-built-from-embedded-dockerfiles.md) — both Dockerfiles are **`include_str!`ed into the binary** and the daemon is handed a **tar on stdin** (`docker build -`), because a context *directory* is a path resolved in the host's namespace — the empty-root-owned-directory landmine that cost HS-027/HS-031/HS-037 a cycle each — and the archive is byte-reproducible (`uid`/`gid`/`mtime` zero) so the daemon's cache sees the same context twice; the build's **output goes to a temporary file** (a pipe nobody drains deadlocks at 64 KiB) and its stdin is written by a spawned thread so `BUILD_TIMEOUT` (20 min, a first build installs pi) can actually fire; `holosmith-proxy:<version>` is `alpine:3` **plus openssl and ca-certificates** because `hs_key` spawns `openssl s_client` (ADR-0048) — `FROM scratch` would make every model call a 502 — and `agent-image:<version>` is `node:24-bookworm-slim` because pi is a node CLI, with git, the configured toolchains, the binary for helper subcommands, `USER node` (the base's uid, which the gate compares with the invoking user's) and both bases pinned by **manifest-list digest** so one Dockerfile resolves per architecture; the three facts and the toolchain list arrive as **build arguments** (`pins/pi.txt` stays the only copy of the pin) and are written as the five **`org.holosmith.*` labels**, which are the skip rule — `toolchains` exists so a changed config rebuilds instead of reading `satisfied`, and **`binary-sha256`** because `git describe --dirty` names the same tree twice, so two builds of one dirty tree would otherwise compare equal over different bytes — read through one `images::Images` seam by both step 3 and `doctor`'s `image` finding, whose arms are equal → pass, differing → fail naming every key, **none of the labels present → pass with a remark** (`pi-agent:local` is a supported machine), and a daemon that answers a run but not an inspect → fail; **"the configured toolchains" becomes the config key `agent_toolchains`** (default `["python3", "ripgrep"]`, an empty list allowed, a blank name refused), which is why `KNOWN_KEYS.len()` is 33 and the golden file moved; the skip rule is labels only — no build timestamp and no image id, because both change on a rebuild of identical inputs; a **build failure names the failing instruction, the layer and the child's last line**, and a failed `docker build -t` leaves no tag (measured) while an older image under an existing tag stays, which is why absence is never the read; the **architecture guard** compares `{{.Server.Arch}}` with `HOLOSMITH_TARGET` once before the first build, because a `docker_host` on another architecture would otherwise build an image whose entrypoint cannot start; the two proxies stop **mounting the host's binary** (the mount that was why a `serve` on an invisible tmpfs started no proxy) and run the image with `--entrypoint /usr/local/bin/holosmith`, and `proxies::start_*` answers a sentence naming the image and `server deploy` when it is absent; the gate gains **`case_server_images` first among the cases whose boot starts the proxies** (it owns the absent state and *asserts* it, checks the five labels, the agent image's contents, both proxies answering from the proxy image with no binary bind, a second run `satisfied` with unchanged image ids, and `doctor --full`'s label pass; it **keeps both images** because every later `serve` boot starts the proxies from them), while the **broken-Dockerfile arm is `tests/images.rs`**, not a case, because the Dockerfiles are embedded and a case could only break a copy.
