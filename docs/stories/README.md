## What a story is

Each story is a vertical slice: it touches every layer needed to produce an observable outcome, and it ends with something you can show. A story is **not** "write the git layer" or "add the events table" on its own.

Every story carries:

| Field | Meaning |
| --- | --- |
| **As / I want / so that** | The user-visible value. The actor is the operator, the agent, or the maintainer. |
| **Size** | `XS` ≤ 2h · `S` ½–1 day · `M` 1–2 days · `L` 2–4 days. Anything larger was split. |
| **Blocked by** | Story ids that must be closed first. No other ordering is implied. |
| **Spec** | Which spec items the story implements. This is how coverage is audited. |
| **Demo** | The one thing you show when it is done. If you cannot show it, the story is not done. |
| **Acceptance** | Checkboxes, each independently verifiable. Spec numbers are quoted, not paraphrased. |

**Definition of done:** acceptance criteria met, `scripts/verify.sh` extended with at least one case and green, the demo performed, and the spec updated if the story changed a decision.

## Decisions taken while slicing

Eighty-two decisions were made that the spec does not make. Each has an ADR because each is hard to reverse, surprising to a later reader, and the result of a real trade-off.

- [ADR-0001](../adr/0001-build-session-lifecycle-before-docker.md) — the session lifecycle is built against the stub backend before Docker exists. Consequence: there are two fakes, the in-process stub backend and the in-container fake pi, and they are not the same thing.
- [ADR-0002](../adr/0002-security-guards-before-endpoints.md) — the browser guards and network isolation land before the features they protect.
- [ADR-0003](../adr/0003-verification-checks-as-story-gates.md) — V1–V11 are acceptance gates on stories, plus one closing verification run.
- [ADR-0004](../adr/0004-cargo-workspace-with-one-binary-crate.md) — a Cargo workspace with one binary crate. Consequence: `cargo run` from the root needs `-p holosmith`, and `web/` is not a workspace member.
- [ADR-0005](../adr/0005-static-musl-artifacts-proven-without-docker.md) — non-PIE static musl artifacts, proven with `bwrap` and qemu instead of Docker. Consequence: nothing may export `RUSTFLAGS`, and the empty-container run stays open until HS-046.
- [ADR-0006](../adr/0006-one-typed-config-value-loaded-once.md) — one typed `Config`, loaded once from `/etc/holosmith/config.toml` (or `--config`), validated by a three-pass walk that reports every problem at once. Consequence: `config` is settled before `server deploy` writes the file, and `config show` prints unset keys as comments rather than omitting them.
- [ADR-0007](../adr/0007-serve-from-one-assembled-service.md) — serve one assembled axum service from tokio, with the web app embedded and a deadline on shutdown. Consequence: routes are added to a `Routes` and are servable only as an `App`, so a later route cannot skip the middleware HS-005 attaches.
- [ADR-0008](../adr/0008-one-json-error-envelope.md) — every error with a body is `{"code","message"}` and the code is the spec's own name. Consequence: `code` values are effectively an API, and a new code arrives with the story that returns it.
- [ADR-0009](../adr/0009-embedded-forward-only-migrations.md) — the binary opens, asserts and migrates its own database, with numbered SQL embedded at compile time and one transaction per start guarded by SQLite's own write lock. Consequence: the startup banner has eight lines, `serve` owns the data root, and the connection stays out of `AppState` until HS-009 decides how handlers share it.
- [ADR-0010](../adr/0010-browser-facing-guards-are-one-layer.md) — the browser-facing guards are one middleware layer inside `App::new`, so a route added later cannot skip them, and every refusal is the ADR-0008 envelope. Consequence: `GET /api/health` is exempt from all four checks, and no response ever carries a CORS header.
- [ADR-0011](../adr/0011-session-row-id-and-absent-status-check.md) — a session's id is 16 lowercase hex characters generated by SQLite before the insert, and its six states are a Rust enum rather than a `CHECK`. Consequence: no uuid crate, and the state machine HS-012 adds needs no migration.
- [ADR-0012](../adr/0012-create-endpoint-shared-connection-and-cap-refusal.md) — the create endpoint takes the raw body, decides its refusals in one fixed order, and shares `Arc<Mutex<Database>>` with the cap count. Consequence: no `axum::Json` extractor, and validation is shape, not vocabulary, until HS-031 learns pi's real values.
- [ADR-0013](../adr/0013-event-log-single-writer-and-seq-counter.md) — one writer thread assigns every seq from `sessions.last_seq`, commits a batch every 25 ms and broadcasts only what survived. Consequence: the mutex stays and the database actor is deferred; an event a client sees is an event a crash cannot undo.
- [ADR-0014](../adr/0014-event-stream-replay-lag-and-open-stream-registry.md) — a stream subscribes before it replays, drops a lagging subscriber with a `stream_lagged` event, and keeps a per-session count of open streams. Consequence: `futures-core` becomes a direct dependency, and the heartbeat is axum's `KeepAlive` rather than a second writer on the connection.
- [ADR-0015](../adr/0015-one-backend-trait-per-step-and-a-background-provisioner.md) — the backend trait is one method per provisioning step, the provisioner is one spawned task per accepted session, and progress is five `session.status` events. Consequence: `AppState` carries the backend, `backend` becomes a config key with `--backend` overriding it, and the Docker backend refuses every operation until HS-024.
- [ADR-0016](../adr/0016-one-transition-table-and-one-function-that-applies-it.md) — the session states and their triggers are one data table, applied by one function that persists the change and then emits `session.status` with `from`/`to`. Consequence: no production code writes a state anywhere else, a source-level guard proves it, and a step beginning is a payload with `from == to` rather than a table row.
- [ADR-0017](../adr/0017-the-sessions-list-and-one-stream-per-visible-session.md) — `GET /api/sessions` answers `{"sessions":[…],"network_default":…}`, one `EventSource` per visible live session patches a row in place, and the page holds nothing but the DOM. Consequence: the create form's checkbox default needs no second endpoint, HS-061's paging has an object to grow into, and a retry repeats its `Idempotency-Key` while the next create does not.
- [ADR-0018](../adr/0018-the-transcript-contract-and-one-block-per-message.md) — four event kinds (`message.delta` with `message_id`/`kind`/`text`, `message.snapshot`, `turn.start`, `turn.end`) are pinned before their producer exists; a transcript block is keyed by message id and a delta is one appended text node, never a re-read; and the renderer's rules are tested with node's own runner over synthetic frames. Consequence: HS-015 emits these kinds and adds three of its own (ADR-0019), an unknown kind is dropped rather than refused, and the DOM half of the screen stays unverified from source until a browser or the producer exists.
- [ADR-0019](../adr/0019-the-turn-runner-and-the-backends-events.md) — the prompt's transition is the handler's and the way out of `running` is the turn runner's, a backend emits its turn's events but can never move a state, and a prompt is refused with one `409 session_<state>` code per state rather than an umbrella code. Consequence: `SessionBackend::start_turn` takes the event writer, the stub scripts a turn with `msg-<n>`/`tool-<n>` ids, `message.end`, `tool.start` and `tool.end` are pinned before HS-033/HS-034 fill them in, and `last_active_at` moves through one new repository method (`touch`).
- [ADR-0020](../adr/0020-the-abort-ladder-and-how-a-turn-is-cancelled.md) — abort climbs two rungs (clear the queue and ask the agent, then kill the container after `abort_grace`), the backend reports how its turn ended (`TurnEnd`) while the runner still chooses the table row, and the ladder is one routine whose reason is a parameter. Consequence: `running` has two owners on a forced stop and the table decides between them, the resume after rung 2 goes through the provisioner, and the refusal family gains `session_idle`.
- [ADR-0021](../adr/0021-a-steers-frame-and-what-was-delivered.md) — a steer is recorded as a `turn.steer` frame with no message id, the agent is asked before the record is written so the log holds what was delivered, and a `409 session_idle` keeps the guidance in the box rather than resending it. Consequence: a steer block is created per frame (the one exception to ADR-0018's "a message id keys a block"), and the composer's third button is wired.
- [ADR-0022](../adr/0022-the-way-back-and-no-stop-endpoint.md) — resume is the only way back, the cap is checked before its transition so a refused resume never strands a row in `starting`, and `SessionBackend::resume` is still uncalled because the provisioner is what brings a session back. Consequence: nothing in the API produces `stopped` until the eviction, idle-stop and drain stories do, and the page resumes once and retries the refused request once.
- [ADR-0023](../adr/0023-the-delete-flow.md) — the delete flow's snapshot is the request's (so a failed one can answer 409 `unsaved_work` and leave the row untouched) and the removal is a task's; the turn is ended first by the ladder's `end_turn`, which stops and does not resume; the event log goes with the row, which makes the writer drop an event whose session has gone instead of refusing its batch. Consequence: a delete of a running session can take up to `abort_grace` to answer, and a backend failure leaves the row `deleting` for a repeated request to retry.
- [ADR-0024](../adr/0024-the-cap-and-eviction.md) — the create evicts the least recently active `idle` session outside its own lock scope, because a state change is `Transitioner::apply`'s and that takes the lock itself; only `idle` is a candidate, and the victim is `last_active_at`'s. Consequence: a create at the cap with nothing idle still refuses with `cap_reached`, a resume on a full machine still refuses rather than evicting, and the page says in one word that nothing was deleted.
- [ADR-0025](../adr/0025-the-idle-stop-sweeper.md) — the idle stop is a sweeper task on a fixed five-second tick, its candidates are one repository read of every `idle` row past `idle_stop_min`, each stop is one `apply` and one spawned best-effort `stop`, and `idle_stop_min = 0` turns the task off. Consequence: the tick is not a config key (so the gate waits a real minute), the reason vocabulary gains `idle_stop`, and the page says what happened in that reason's own words rather than the cap's.
- [ADR-0026](../adr/0026-the-turn-timeout.md) — the turn timeout is the turn runner's own deadline rather than a sweeper, because the row keeps no per-turn timestamp (`last_active_at` moves on a steer, so a watcher would let a steered turn run for ever) and rung 1 needs the turn future alive to answer; both endings record `turn_timeout`, the runner's `running → idle` when the agent answers and the ladder's `running → stopped` when it does not. Consequence: no new column, no migration, and `turn_timeout_min = 0` builds no timer at all — so the gate can only prove that a short turn is not ended early, not that the deadline fires.
- [ADR-0027](../adr/0027-the-token-budget.md) — the token budget counts a column the event writer adds to inside the transaction that assigns the seq, because the backend emits `message.end` and the runner never sees the frame; the ceiling itself is the turn runner's, polled every hundred milliseconds next to ADR-0026's deadline and climbing the same ladder, and the first policy to fire owns the reason. Consequence: the events repository parses exactly one kind's payload, a turn that settles over its ceiling records the reason instead of being aborted, and a backend that reports no usage cannot trip anything — the screen says so instead.
- [ADR-0028](../adr/0028-the-docker-preflight.md) — the Docker preflight is a startup refusal rather than a per-request check, because item 10 §5 puts the same check in the unit file as `ExecStartPre`; its failures are `Complaint` values (a check and one sentence naming the fix) reported all at once, so `serve`, the Docker backend and HS-045's `doctor` print the same words. Consequence: no new dependency (`df -Pk` and `git --version` are subprocesses, `_ping` is four lines over a std socket), and a check that cannot run — an `ssh://` daemon, a missing `git` — is a complaint rather than a silent pass.
- [ADR-0029](../adr/0029-the-worktree-is-made-by-the-backend-and-recorded-by-the-provisioner.md) — the worktree's five host commands live in one `src/worktree.rs` value that the Docker backend runs off the runtime's worker; the backend answers `Provisioned::Worktree { path, base_commit }` and the **provisioner** writes the row, because a backend may not write one (ADR-0019); `ensure` is idempotent (create or adopt) so a resume re-provisions a worktree that is still there, and the row's `base_commit` wins over the branch's head so `ahead` keeps its starting point. Consequence: no schema change and no `ahead` column — the number is a function on the worktree and `GET /changes` (HS-061) is what publishes it — a step that only **adopted** a worktree is not undone when a later step fails (those commits are the agent's) while a delete removes it like any other, and teardown treats a missing worktree, branch or project repository as success, so a delete cannot wedge on ADR-0023's `deleting` row.
- [ADR-0030](../adr/0030-the-projects-refusals-are-the-creates-422.md) — a project the machine must not mount is refused by the **create** with its own `422` (`git_not_directory`, `submodules_present`, `worktree_config_enabled`) and one sentence, because the provisioner has no request to answer and the spec says "refused with 422 at session creation"; the rules are `worktree::refuse`'s (filesystem reads plus one `git config --type=bool`), the question is `Backends::refuse`'s (the stub mounts no repository, so it refuses nothing), and the read runs on `spawn_blocking`. Consequence: a project the machine does not hold is refused rather than accepted into an `error` row (HS-025's behaviour, changed here on purpose), the refusal is raised after the idempotency lookup and before the cap so a retry still answers its row and a refused create never evicts, the **resume** asks the same question (so a project that became unsafe cannot be reopened), the `extensions.worktreeConfig` read is `--local` (a global key must not refuse every project), a repository git cannot read answers `500 internal` with git's words logged, and the create form prints the sentence alone for those three codes.
- [ADR-0031](../adr/0031-coalescing-in-the-writers-batch.md) — event coalescing is the writer's, in a pure `coalesce(batch)` between `collect` and `commit`, because that batch is spec item 15's "inside each 25 ms commit" and ADR-0013's one place a seq is assigned; a delta merges into the row before it only when the session, the `message.delta` kind, the message id and the delta's own `text`/`thinking` all match, and anything between two deltas ends the run. Consequence: the writer reads a second payload (the repository still parses exactly one, ADR-0027 — a count ADR-0032 widens to three), a payload that is not the pinned shape is passed through untouched and ends its run, adjacent rows of one message and kind may still sit together across commits, and the merge itself can only be shown by a burst — `tests/events.rs` (5,000 → three rows) and `tests/turns.rs` (seven → three) — because the gate's stub paces eight commit windows apart.
- [ADR-0032](../adr/0032-compaction-is-a-per-session-pass-inside-the-lock.md) — compaction is a background task whose per-session pass runs **inside the database mutex the transitioner also takes**, so a turn either started before it (the row says `running` and the pass skips it) or starts after it; the 24-hour window is the spec's fixed number and not a config key (`Compactor::with_window` is how a test chooses one), the fold is one transaction per session bounded by `MESSAGES_PER_PASS` after the already-folded filter, the snapshot takes the highest removed seq and never moves `sessions.last_seq`, and nothing is broadcast. Consequence: `message.end`, tool frames and turn boundaries are never removed, a delta whose payload is not the pinned shape stops the whole session for that pass rather than losing text, and the only way to show the window from the shipped artifact is to stop it, age the log and start it again — which is `case_compaction` and the story's own demo.
- [ADR-0033](../adr/0033-history-truncation-and-pagination.md) — a stream opened with no `Last-Event-ID` is replayed from the **lowest seq of the `history_window`-th most recent message**, found by a backwards scan over the message-bearing kinds so a block is always whole; the cut is computed in the stream's read step and only for a client with no resume point, and it is announced by a `history.truncated` frame carrying `{before_seq, turns_before}` and **no** SSE `id` (it is not a stored event). Consequence: the window is a config key (`history_window`, default 50, `0` refused), a page is `seq < before ORDER BY seq DESC LIMIT n` and therefore stable under concurrent writes by construction, `before` is required with a new `422 bad_query`, and the page numbers a turn from `turns_before` rather than from the frames it was not sent — `case_history` and `tests/history.rs` are where the two halves meet.
- [ADR-0034](../adr/0034-the-project-backup-is-one-verified-bundle-per-day.md) — the `project_backup` bundle is **one git bundle per project per calendar day (UTC)**, named `<data>/backups/<project>-<YYYY-MM-DD>.bundle`, so "has today's been taken" is a `stat` and the name is also the retention rule's sort key; it is written aside, checked with `git bundle verify` and only then renamed into place, so a file under the final name is always one git can read, and the last seven days per project are kept. Consequence: the **create** takes it — awaited, after the row exists and before the provisioner is handed the session — because the story says "before the first session of each day", and every failure is one `warn` line that does not block the session, because a broken safety net must not become an outage.
- [ADR-0035](../adr/0035-the-hardened-git-mounts-are-one-value.md) — the hardened `.git` mounts are one value (`container::Mounts`: worktree at `/work`, the repository's `.git`, and `.git/hooks`/`.git/config` stacked on top of it read-only), and **V1 passes as specified** on a real daemon, so the spec's narrower fallback is not applied. Consequence: the repository's three mounts keep their **host path inside the container**, because a worktree's `.git` *file* holds an absolute `gitdir:` under `<project>/.git/worktrees/<id>` and any other container path would point git at something nothing mounted; `--user` is deliberately not passed (the image's default user must be non-root, and the gate reads `id -u` instead of guessing a uid the deploy step owns); a mount source that is missing or of the wrong kind is refused **before** `docker run`, because Docker creates a missing source as an empty root-owned directory and would mount nothing; and the image became the config key `agent_image` (default `agent-image:<version>`, this machine's `pi-agent:local`).
- [ADR-0036](../adr/0036-hs-028-fills-the-network-step.md) — HS-028 fills the **network** step as well as the container one (a container cannot join a network that does not exist, and spec item 6's run line names `--network agents_<id>`), creates it `--internal` because that *is* the isolation, and leaves the `egress` network, the proxies, the startup self-test and orphan cleanup to HS-036. Consequence: the container runs **detached** with `sleep infinity` as its placeholder command until HS-031 attaches pi's stdio, the limits are three integer keys (`container_cpus` 2, `container_memory_mb` 4096, `container_pids` 512, each refusing `0` because Docker reads zero as *unlimited*), the `docker` CLI is one module that passes `-H` rather than inheriting `DOCKER_HOST`, `Mounts::check` runs before every `docker run` (ADR-0035's measurement), and the flags are asserted by `docker inspect` in `tests/container.rs` while the gate asserts the step *order* and that nothing is left behind.
- [ADR-0037](../adr/0037-a-per-session-start-lock.md) — a container start is `docker rm -f` **then** `docker run`, in one function, because `--rm` removes an exited container only *after* `docker stop` has already returned (measured), and because a container the process lost track of has to be replaceable; the two calls are serialised per session by a `tokio` mutex so two starts cannot interleave into "the container name is already in use". Consequence: `SessionBackend::resume` gets a body at last — network then container, no worktree, because the worktree step's `ensure` is create-or-adopt (ADR-0029) — and `stop` becomes `docker stop --time 10` with the expected-stop flag and the exit classification still HS-030's.
- [ADR-0038](../adr/0038-the-expected-stop-flag-and-the-exit-classifier.md) — the expected-stop flag is a `sessions` column that no client is sent (`Session` is the API's body, and phase 1b may not change the API), written by one `Stopper` that the sweeper, the eviction and the ladder's forced rung all use, and taken with a compare-and-swap because SQLite's `RETURNING` on an `UPDATE` answers the row *after* the write; a clean exit becomes its own table row (`pi_exit`) because item 8's "exits unexpectedly → error" is what item 6 replaces for code 0; and the classifier is a pure function whose `Exits::record` has **no production caller yet** — HS-031's attached stdio is the only thing that can observe an exit in this build, since the container runs detached and `--rm` takes it away a moment after it stops. Consequence: the demo is half-showable (the flag from the artifact, the three outcomes from `tests/exit.rs`), and `session.log` gets its writer.
