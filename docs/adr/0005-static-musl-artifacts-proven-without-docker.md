# Only statically linked musl artifacts, proven without Docker

The only artifacts we ship are `x86_64-unknown-linux-musl` and `aarch64-unknown-linux-musl` release builds, and both must be plain `ET_EXEC` static binaries, not static PIE: the two musl targets carry `rustflags = ["-C", "relocation-model=static"]` in `.cargo/config.toml`, so `file` reports `statically linked` for both and `readelf -d` prints "There is no dynamic section in this file". SQLite is compiled from source with the `bundled` feature for the same targets, so the C toolchain crosses as well.

Why non-PIE: the default for `x86_64-unknown-linux-musl` is `static-pie linked`, which is equally static at run time but does not satisfy the spec's stated check (`file` reports statically linked) without an explanation every reader has to reconstruct. The trade is real and worth recording: we give up address-space randomisation for the main binary in exchange for an artifact whose `file` output is self-evidently what the spec promised, and a deployment check that cannot be misread.

Why verify without Docker: the machine this is built on has no Docker daemon, so "runs in an empty container" would otherwise be an unproven claim held by hope from HS-001 until HS-046. `scripts/check-static.sh` replaces it with two stronger, local checks — the x86_64 artifact runs inside `bwrap` with an empty root and only the binary bound (no `/lib`, no `/usr`, no loader), and the aarch64 artifact runs under `qemu-aarch64-static` when that optional dev tool is on `PATH`, printing a single loud `SKIP` line when it is not. Neither check may fail the build because of a missing tool, and no repo script downloads anything: the emulator is a machine-local prerequisite, documented in `docs/build.md`, not a declared dependency.

What this does and does not prove: it proves the artifact has no dynamic loader and no userspace dependency, on both architectures. It does not prove anything about a real container runtime; that is the empty-container run on real x86_64 and aarch64 Docker hosts in HS-046 and the deploy smoke test in phase 2, and it stays an open acceptance item until then rather than being quietly claimed here.

Consequence we accept: nothing in the repo may export `RUSTFLAGS`, because cargo silently ignores `target.*.rustflags` from config when that variable is set — the build would produce static-PIE again with no error. `check-static.sh` therefore asserts the property on the produced artifacts, so a future `RUSTFLAGS` mistake fails loudly instead of shipping a differently linked binary.
