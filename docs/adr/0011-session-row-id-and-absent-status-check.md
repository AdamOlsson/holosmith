# The session row: an id SQLite makes, no CHECK on the status, and one file that owns the SQL

This is the story every later one hangs off: it is the first table that is not the migration registry. The spec's "Data model and API changes" names eight of the columns and the lifecycle implies the rest — `stopped_at` from item 15's retention job, `last_active_at` from item 7's LRU eviction, and `id`, `project`, `model`, `thinking`, `base_commit`, `created_at` — while the story's own note fixes the one thing the spec left open: `worktree` stays `NOT NULL` and holds `''` until the provisioner runs. This records the four decisions that the schema and `src/sessions/` had to make together: where the id comes from, why `status` has no `CHECK`, what `''` in `worktree` means, and why the repository borrows the database's connection instead of owning one.

## Measured before deciding

Measured on the build machine against `rusqlite` 0.37 / SQLite 3.50.2 with the `bundled` feature, and by the tests this story adds.

- **`SELECT lower(hex(randomblob(8)))` is always 16 lowercase hex characters.** 1000 samples: every one was 16 characters and every byte was `[0-9a-f]`.
- **A `TEXT` primary key is not `NOT NULL` in SQLite.** `CREATE TABLE t (id TEXT PRIMARY KEY)` accepted `INSERT … VALUES (NULL, 'a')`, twice: the rowid alias rule applies only to `INTEGER PRIMARY KEY`, so `id` can hold `NULL` and several such rows. Accepted rather than defended, because only the repository writes an id and every read is by id: a `NULL` id is unreachable except through raw SQL.
- **A column default plus `RETURNING` works on this build.** `CREATE TABLE u (id TEXT PRIMARY KEY DEFAULT (lower(hex(randomblob(8)))))` followed by `INSERT INTO u (v) VALUES ('x') RETURNING id` answered a 16-character id. It is still rejected below, for a reason that is not capability.
- **A duplicate `client_key` fails as `UNIQUE constraint failed: <table>.client_key`,** and many `NULL`s are accepted: `UNIQUE` treats every `NULL` as distinct, which is exactly what needs.
- **`ALTER TABLE … DROP CONSTRAINT` is a syntax error.** So a `CHECK` written today cannot be changed later; SQLite's 12-step table rebuild is the only way, and it would have to happen inside a forward-only migration.

## The id is generated by the database and read before the insert

`SELECT lower(hex(randomblob(8)))` — 16 lowercase hex characters, produced by the database that stores them. Hex is forced by every place the id is pasted into: a git branch `agent/<id>`, a container name `s_<id>`, a worktree directory `<projects>/.worktrees/<id>` and a session directory `<data>/sessions/<id>/` — it needs no quoting on a command line, no escaping in a path, and no case folding in a container name. 64 bits of randomness is ample for one operator's machine.

The repository runs that query **before** the insert and passes the value in, rather than leaving it to a column default:

- the id is then a value the caller can log, hand to a provisioner and assert the shape of, instead of something only the database knows;
- the id's shape lives in the one file that owns the table's statements, not in a migration, so changing it later is an edit plus a test rather than a table rebuild;
- `create` returns the row it read back, so the returned `Session` is what a later `get` sees.

Rejected: `DEFAULT (lower(hex(randomblob(8))))` with `INSERT … RETURNING id` (works, measured above, but moves the shape into migration 0002 and makes the id something the repository learns only from the row it just wrote), the `uuid` crate (a dependency for 64 bits of randomness, against "do not add a crate"), and a hand-rolled Rust PRNG (the kind of code that is wrong in a way tests do not catch).

## `status` has no `CHECK` constraint

The six values — `starting`, `idle`, `running`, `stopped`, `error`, `deleting` — live in a Rust `Status` enum whose `FromStr` refuses anything else with the offending text. The column is plain `TEXT NOT NULL`.

- **A corrupt row is a read-time error that says what it holds.** `RepoError::Status("ended")` rather than a bare "invalid status", and the unfiltered list reports it instead of dropping the row. Proved by `a_corrupt_status_is_reported_with_the_text_it_holds`.
- **A later change owns the transitions and will change this set.** Item 8 is a state machine with reasons, resumes and forced aborts; a `CHECK` in a migration would have to be rewritten by the measured 12-step rebuild the first time the set or a reason changes, and ADR-0009's expand/contract discipline makes every one of those changes expensive.
- **The cost is real and accepted:** SQLite will store any string in `status`, so a hand edit or an older release can write a value the enum refuses. That surfaces where it is cheapest — one row, one error, naming the text — instead of as a `CHECK` that could only be relaxed by rebuilding the table.

The same reasoning is why `Status::ALL` exists as one array: the state filter, the error message and the tests read one list, so adding a status is one edit.

The glossary's term is **State** and the code's name is `Status` — the glossary entries for `State` name the `sessions.status` column and the `Status` type, so a reader who searches for either finds the other. That is the drift that otherwise costs a later reader an afternoon.

## `worktree` is `NOT NULL` and `''` means "no worktree yet"

The story note settles it: `''` for stub and unprovisioned sessions rather than a nullable column. A nullable `worktree` would make every reader answer "is `None` the same as `''`?" separately, and the provisioner would have to keep two spellings of "not yet". The column that is genuinely absent before provisioning is `base_commit`, and it stays `Option<String>`.

## The repository borrows the connection; it does not own it

`Database::sessions(&self) -> SessionRepository<'_>` lends out the connection the database already holds. ADR-0009 deliberately left that connection outside `AppState` and left the single-writer question, so this story adds no new owner and no `connection()` accessor: a `Database` that exposed one would let a caller write any SQL, and "every sessions statement lives in `repository.rs`" would go back to being a review note.

Rejected: moving the `Connection` into the repository (a `Database` would become a shell that hands out its only field, and `schema_version` and the startup lock would have to move with it), and a `pub fn connection(&self)` accessor (rejected above: it defeats the point of having a repository).

Every statement is in `crates/holosmith/src/sessions/repository.rs`: the id query, the insert, the two single-row reads, the list and the status update. A unit test there walks `src/**` and fails if `FROM sessions`, `INTO sessions`, `UPDATE sessions` or `DELETE FROM sessions` appears in any other file, naming the offending file and line. It is the same tripwire shape as ADR-0009's `_contract_` naming test and ADR-0007's one-`.layer(` pin: `tests/**` is deliberately outside the walk, because a test has to read the table's own schema (`PRAGMA table_info`) and write a status the enum refuses in order to prove the read-time error.

## Consequences

- The schema becomes 2. `SCHEMA_VERSION` is bumped in the same change as the migration, so the startup banner's `schema 2`, `version --json`'s `schema_version`, `tests/version_cli.rs`'s derived assertion and `scripts/verify.sh`'s `case_schema_version` all follow from one literal. `tests/db_migrations.rs`'s applied-set assertions now name two rows instead of one.
- Two indexes ship with the table — `sessions_status` and `sessions_last_active` — because the only two queries that will not go by primary key are "live sessions by status" (the cap) and "least recently active" (eviction), both that story's, and adding them now is cheaper than a contract migration later.
- `now` is a parameter on `create` and `set_status`, exactly as it is for `Database::open`: a test asserts the timestamp instead of racing the clock, and the repository never reads the clock.
- `set_status` moves `stopped_at` with the status — `now` for `stopped`, `NULL` for everything else, which is item 15's "cleared on resume" — and deliberately does **not** touch `last_active_at`, which is activity: and own when it moves.
- `create` writes `worktree = ''`, `base_commit` as given, `status = starting`, `created_at = last_active_at = now`, usages 0 and `stopped_at` `NULL`; nothing else in this story writes a row.
- Not here, and not implied: `POST /api/sessions` and its validation, the events table and the single writer, the transition rules, `push_subscriptions`, usage accounting and any `AppState` change.
- `Session` derives `PartialEq`, so the story's demo — create, drop the `Database`, reopen the same file, `get`, compare the whole struct — is one assertion rather than fifteen.
