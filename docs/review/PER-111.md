## Standards

**S1 — P1. New logic, no measurement: `Real::joining`'s `joins` policy.** `promote.rs:179-203` adds `joins` to the drain closure, set at `:158-165`; the only construction sites are `commands/rollback.rs:56` and `commands/upgrade.rs:63`. `promote.rs` has no `#[cfg(test)]` module at all, and no test builds a `Real`, so flipping `Self::named(config, "rollback", true)` to `false` reddens nothing in `cargo test`; `case_rollback` never produces `drain::ALREADY` (its drain is the first on its own boot). ADR-0083:110-111 says "Both readings are tested" — the *verbs'* readings are (`tests/upgrade.rs:387-391`, `tests/rollback.rs::a_rollback_joins_a_drain_somebody_else_started`); the policy that produces them is not. Defeats the repo rule "a test that cannot fail is worse than no test" (`RESUME.md` §6). *Fix:* one unit test over `commands::drain`'s fake socket — `Real::new` answers `Already`, `Real::joining` answers `Drained`.

**S2 — P2. The shared unit refusal speaks as a promotion and omits the machine's state.** `rollback.rs:113` calls `promote::write_unit` *before* the drain (ADR D6), so its failures leave the machine serving — but the sentences (`promote.rs:711-735`) say "a promotion writes it" and carry no "nothing was drained and nothing was switched" clause, unlike every other pre-drain refusal in `rollback.rs` (PER-110's S1 class, `docs/review/PER-110.md:4`). *Fix:* in `rollback.rs:113`, `.map_err(|said| format!("{said} — nothing was drained and nothing was switched"))`, and s/promotion/release verb/ in those two sentences.

**S3 — P2. A refusal that contradicts its own listing.** `rollback.rs:241-250`: "this tree does not hold it ({}): … so there is no release list to go one back in" — then `listing()` prints that list. Reachable whenever `current` names a release whose `holosmith` was deleted (`live()`, `:200`, does not require the binary). *Fix:* delete the "no release list" clause.

**S4 — P3 (judgement, Duplicated Code).** `Tree`/`set_mtime` (`release.rs:433,466`) re-implement `tests/release.rs:19-38`'s `support::TempDir` + `tree()`; `src/rollback.rs`'s tests add a third temp-dir type. Three order tests fit `tests/release.rs` beside the module's other integration tests.

**S5 — P3.** `deploy.rs:1723-1734`: a rollback "writes the release tree" — it writes the symlink and, sometimes, the unit. Say "writes into the release tree".

**S6 — P3.** ADR-0083:188-191 says nothing about `upgrade` changed except one sentence and the switch-back prefix; a promotion whose *restart* fails no longer prints "health: no answer with … in 20s" (that line left `serve_with` for `poll`, `:958-965`). An improvement, unrecorded — and unmeasured (`case_upgrade`'s stand-in never fails a restart).

**S7 — P3.** ADR-0083:178 "`cp -r` reverses it" and `notes.md:2951` "their order collapses to the tiebreak" are two different claims about one unmeasured fact; I cannot check either without a shell.

Worst: S1.

## Spec

**Covered:** bullet 1 (drain → switch → restart → poll, asserted by `tests/rollback.rs`'s trace and `case_rollback/switch/before`), bullet 2's placement (before the drain, `current` unmoved), bullet 3 (gate: the drained session back `idle`), bullet 4 (`not_live`, `rollback.rs:176-198`).

**S1 — P2. Bullet 2's "clear explanation" is a promotion's explanation.** `refuse_older_schema` (`promote.rs:529-557`, called at `rollback.rs:92`) differs between verbs only in `subject`, so a rollback is told "build a release from the current tree (`holosmith build`), or restore a database this release understands" — i.e. go forward, or lose data — and nothing about `--to`, the releases the tree *does* hold, or the way forward again. The rollback's true next step ("name a release whose schema this database understands with `--to`") is absent. ADR-0083 D4 defends the shared *measurement*, not a shared remedy. *Fix:* give the function a per-verb `remedy: &str`, or append the `--to` clause on the rollback's side.

**S2 — P2. An assertion that cannot fail, under a false comment.** `tests/rollback.rs:508-512` asserts `world.tags == TAGS…`, but `world.tags` is built from `TAGS` at `:226`: a constant compared with itself, commented "the fixture really was a release the tree counted before it was broken". The `World::tags` field exists only for it. *Fix:* assert `Release::of(&world.target).history()` contains `"two"` *before* the binary is broken — or delete the field and the assertion.

**S3 — P3, scope creep.** `--to` accepts a *newer* release, "forward again" (ADR D3); not asked for, recorded, harmless.

**S4 — P3, recorded limit.** Item 10's "That makes the symlink rollback safe without restoring the database" sits beside bullet 2's refusal of every rollback across a schema-advancing release (`GLOSSARY.md` Rollback entry states both). ADR-0082's follow-up for HS-045/HS-049 covers it.

**S5 — P3, recorded limit.** Bullet 3 is measured only between three copies of one artifact; ADR D8 records the release built before HS-078 that leaves a session `stopped` (an allowed state).

Worst: S1.

Not verified (no shell): that `fmt`/`clippy -D warnings`/`cargo test` are clean, the new test counts (notes claim ten in `tests/rollback.rs` — I count ten), and `case_rollback` end to end.

| S1 (Standards) **P1** — `Real`'s drain policy is untested | fixed | `promote::tests::a_promotion_refuses_a_drain_somebody_else_started_and_a_rollback_joins_it`: a fake admin socket that writes `state: already draining` then `result: drained`, driven through both constructors — `Real::new` answers `Already`, `Real::joining` answers `Drained`. | S7 (Standards) P3 — two claims about `cp -r` | fixed | The ADR now says what `docs/notes.md` says and what is true: a `cp -r` stamps every release with the moment of the copy, so the order collapses to the tag tiebreak (a name order, which is what D2 refused). "Reverses it" was wrong. |

| S4, S5 (Spec) P3 — recorded limits | dismissed | Both are already recorded: the schema-advancing rollback in ADR-0082's "What this does not measure" and ADR-0047, and the pre-HS-078 `stopped` session in ADR-0083 D8 (`stopped` is one of the two states bullet 3 allows). |
