**Correct** (verified, not taken on trust):

- The refusal really is before any child: `uninstall::run`'s `args.purge && !args.force` block (uninstall.rs:266) returns `Err` from `live_sessions` (uninstall.rs:310) before the four steps at uninstall.rs:283, and `tests/uninstall.rs::a_purge_refuses_over_a_live_session_and_removes_nothing` re-reads the row afterwards — a measurement, not a word.

- One reader per fact holds: `deploy::wait_for_health` → `doctor::health_answers` → `http::health::ask` (deploy.rs:1932), `db::recorded_without_migrating` now goes through `Reader` (db.rs:424-429), and no second `/api/health` request survives anywhere in `src/`.

### Standards axis

| # | Sev | Finding |
|---|---|---|
| T1 | **P1** | **`status` prints a proxy *state* it did not measure.** `status.rs:140-151`, with the comment at `:144` "Both arms are a measurement: the daemon answered" — but `proxies::running` → `Docker::running` (docker.rs:379-382) and `succeeds` (docker.rs:92-97) fold *every* daemon error into `false`. A `docker_host` the operator cannot reach, a stopped daemon, or simply an account not in the `docker` group makes `status` print `proxy hs_egress not running` / `proxy hs_key not running` as a **measurement**, which is exactly the "prints a number where it could not look" the module and ADR-0059 D1 forbid. ADR-0054:137-144 states the opposite rule for this read ("They are **not measured** (`unknown`) when the `docker` check failed"), and `doctor`'s `proxy` (doctor.rs:786-795) implements it; `GLOSSARY.md`'s new *Status command* entry ("Each value has three arms") is therefore false for two of its twelve lines. The gate cannot catch it: `case_status`'s proxy check (verify.sh:6262-6271) reads the same collapsed answer, so it passes whether the daemon answered or not (brief item 1 and item 5). **Smallest fix:** ask the daemon once (`preflight`'s `docker` finding, as `doctor` does at doctor.rs:206-212) in `commands::status::run` and emit `unknown: not measured: the daemon did not answer` for both proxy lines when it did not pass. |
| T2 | P2 | **`Reader::open` turns "cannot look" into "never served".** db.rs:152-155 answers `Ok(None)` whenever `Path::exists()` is false, and `exists()` is false on *any* stat error, not just `NotFound`. Two consequences in this diff: `status::counts` prints six measured zeros (status.rs:194), and `uninstall::live_sessions` (uninstall.rs:310-333) answers `0` live sessions, so `--purge`'s refusal (uninstall.rs:266) never fires and the data root is deleted without the check. This contradicts ADR-0054:100-102 ("A missing file is `pass` … a file that cannot be read is `fail`") and `Reader`'s own doc ("a file it cannot read is the caller's finding to make, not a silent absence"). **Smallest fix:** `std::fs::metadata`, `ErrorKind::NotFound` → `Ok(None)`, anything else → `Err`. |
| T3 | P2 | **The purge sweep filters networks with the container prefix and swallows the daemon's error.** uninstall.rs:661-663 lists with `NAME_PREFIX` (`"s_"`, container.rs:59) although session networks are `agents_<id>` (`NETWORK_PREFIX`, container.rs:62). It works only because Docker's `--filter name=` is a substring match and `agents_` contains `s_`. `.unwrap_or_default()` then makes a daemon that cannot list indistinguishable from "no session networks": `refused` stays empty, so the line "with N session container(s) and M session network(s)" (uninstall.rs:614-624) claims a count it did not measure, while container failures *are* recorded. **Smallest fix:** `container::NETWORK_PREFIX`, and push the `Err` into `swept.refused`. |
| T4 | P2 | **A failed `systemctl` is read as a negative measurement.** uninstall.rs:342-346 uses `is-enabled`'s remark only as a boolean (`remark().is_none()`), so `Answer(Some("it could not be run: …"))` (uninstall.rs:422-432) is indistinguishable from systemd answering "no such unit", and the `nothing` sentence asserts "`systemctl is-enabled holosmith.service` **answers** that systemd knows of none" on a machine where nothing answered at all (no systemd, no `systemctl`). Brief item 4 in the opposite direction: the remark does not hide a failure here, it manufactures a measurement. **Smallest fix:** carry the `Answer`'s sentence into the `nothing` line ("systemd could not be asked (…)"). |
| T5 | P2 | **A failed purge says nothing was removed after removing containers and networks.** `remove`'s failure sentence (uninstall.rs:465) is "nothing was removed before it, so the tree is as this run found it", but `data()` calls `sweep` (uninstall.rs:582) *before* `remove(root, true, …)` (uninstall.rs:607), and the `Failed` line drops `swept` entirely. So a `--purge` whose `rm -rf` fails reports that nothing was removed while every `s_<id>` container and `agents_<id>` network is gone. **Smallest fix:** give the purge's `rm` its own sentence, or thread what the sweep removed into it. |
| T6 | P2 | **The one arm that changes the exit code is untested.** `only_a_failed_read_changes_the_exit_code` (status.rs:322) builds a `Report` by hand, so deleting `counts`'s `Err(sentence) => vec![Line { key: "sessions", value: Value::Failed(..) }]` (status.rs:214-218) and printing zeros instead leaves every unit test green; `case_status` only ever asserts exit 0 (verify.sh:6239, 6283), so nothing in the gate measures exit 1 either. Answer to brief item 6 ("which could pass with the behaviour removed"): this one, and it is the story's headline rule. **Smallest fix:** one test that writes a non-database at `<data>/app.db` and asserts the `sessions fail:` line plus `report.failed()`, and one `case_status` assertion for exit 1. |
| T7 | P2 | **`follow`'s doc claims behaviour the code does not have.** logs.rs:136-138: "a file that shrinks (a log rewritten) is re-read from the start". `follow` (logs.rs:139-167) opens the file once and never seeks, so after a truncation `read` returns `0` forever and nothing appended after it is ever printed (a replaced inode is worse). `session.log` is append-only in practice, so this is a doc/code contradiction rather than a live bug — but the sentence is the kind of claim this repo treats as a contract. **Smallest fix:** delete the clause, or `seek(SeekFrom::Start(0))` when `metadata().len()` is below the running offset. |
| T8 | P3 | `deploy.rs:62-66`: `ADMIN_DIR` is documented as public "because … HS-050's `uninstall` … [has] to know" `/run/holosmith`. `uninstall` never names it, nor `Target::etc_config()`, so the deployed `config.toml` and the admin socket dir survive every uninstall (which makes ADR-0059 D6's "keeps" list non-exhaustive, since neither is data). Either remove them — they are installed, not data — or fix the comment and extend D6. |
| T9 | P3 | Duplicated code (baseline, judgement call): `commands/uninstall.rs:91-95` is `commands/deploy.rs:90-94` byte for byte, doc comment included; the resume builder at `commands/uninstall.rs:74-89` is the deploy's shape again. A four-line `absolute` in `commands/mod.rs` would carry both. |
| T10 | P3 | Gate measurement gaps in `case_status`: the first six-status loop sums into `total` (verify.sh:6251-6257) and the value is never read before the second loop resets it (verify.sh:6295) — that summation measures nothing; and the uptime assertion `grep -qxE "uptime ($uptime|$((uptime + 1))|$((uptime + 2)))s"` (verify.sh:6247) is satisfied by a fresh boot's `uptime 0s`, i.e. by a hardcoded `0`. Minimal fix: drop the dead sum; compare the after-run's uptime with the before-run's (or sleep ~2 s and require it to have moved). |
| T11 | P3 | Two uninstall test names over-claim what they assert: `the_system_path_asks_systemd_and_prefixes_its_write_with_sudo` asserts that **no** `rm`/`sudo` child ran (its own comment says so — the sudo prefix is measured by `a_purge_is_one_sudo_prefixed_child_on_a_system_path_install`), and `the_proxies_and_the_egress_network_go_containers_first` records container and network removals in separate vectors and never asserts the order its name claims. |

**Merge verdict: BLOCK** — one P1 (T1: `status` reports proxy *state* it did not measure, against ADR-0054:143-144 and the story's own D1), plus eight P2s, four of them (`T2`, `T3`, `T4`, `T5`) all instances of the single theme the brief pins: the report saying more than it measured. No test command is needed from a supervisor to confirm these — every finding is a straight read of the shipped source — but T6's fix needs a new test and T10's needs a gate edit, after which `bash -n scripts/verify.sh`, `cargo test` and the 75-case gate should be re-run.
## Resolution

Every finding was triaged in the same session. "Fixed" means the code, the test or the doc changed and the gate was
re-run; "dismissed" carries the citation the workflow requires.

| # | Sev | Verdict | What changed |
|---|---|---|---|
| T1 | P1 | **fixed** | `status` asks `preflight::daemon` **first** and makes both proxy lines `unknown: whether it is running was not measured: …` when the daemon did not answer, because `Docker::running` folds every daemon error into `false`. New: `preflight::daemon` (public, the one spelling of the check `report_with` also uses), `status::proxies`, two unit tests (`a_running_proxy_is_measured_from_the_daemons_answer` over a fake `_ping` socket, `a_machine_that_never_served_…` asserting the `unknown:` arm). ADR-0059 D1 records the rule and why a missing daemon is not a failure. |
| T2 | P2 | **fixed** | `db::Reader::open` matches `ErrorKind::NotFound` and returns the error for any other stat failure, so "cannot look" is no longer "never served" — for `status`'s counts and, worse, for `--purge`'s live-count refusal. |
| T3 | P2 | **fixed** | the purge sweep lists with `container::NETWORK_PREFIX` (not the container prefix, which only worked because `agents_` contains `s_`) and pushes the listing's error into `swept.refused`, so the line's count is a measurement or says what it could not measure. |
| T4 | P2 | **fixed** | `uninstall::Answer` is now `Yes`/`No(line)`/`Unasked(line)`, so "systemd said no such unit" and "systemctl could not be run" produce different sentences — the `nothing` line no longer claims an answer no program gave, and `disable --now`/`daemon-reload`'s remarks say which of the two happened. |
| T5 | P2 | **fixed** | a failed purge's `rm` sentence now names what the sweep already removed (containers, networks, and anything the daemon refused), instead of claiming "nothing was removed". |
| T6 | P2 | **fixed** | `status.rs`'s `a_database_that_cannot_be_read_fails_the_sessions_reading_rather_than_printing_zeros` puts a non-database at `<data>/app.db` and asserts the `sessions fail:` line, `report.failed()` and the absence of `sessions idle 0`; `case_status` gained the same arm against the artifact (exit 1, the `fail:` line, no counts). |
| T7 | P2 | **fixed** | `logs::follow`'s doc no longer claims a re-read on truncation: the limit is stated (a shrunk file is not re-read, a replaced inode is not followed) and why it is acceptable (`session.log` is append-only; a session's directory is removed, never rewritten). |
| T8 | P3 | **fixed** | `deploy::ADMIN_DIR`'s doc no longer says `uninstall` reads it, and records the decision: the admin directory and the deployed `config.toml` are **kept** (neither is data, neither is named by the spec's teardown row, and HS-051's socket lives in the directory). ADR-0059 D6's keeps list now names both, so it is exhaustive. |
| T9 | P3 | **fixed** | `absolute` lives once, in `deploy::absolute`; both resume printers use it. |
| T10 | P3 | **fixed** | the dead `total` summation in the first loop is gone; the after-run's uptime is compared with the health answer's `uptime_s` **two seconds later** (so a hardcoded `0s` fails), and the case gained the exit-1 arm. |
| T11 | P3 | **fixed** | the two test names now say what they assert (`a_system_path_run_with_no_unit_file_asks_systemd_and_writes_nothing`), and the Fake records every removal **in order** so "containers before the network" is asserted rather than claimed. |
| S1 | P2 | **dismissed** | "last health per registered machine" cannot be measured before the registry exists: `docs/stories/phase-2-deployable-mvp.md` HS-050's non-goals and ADR-0059 D1 both put it in HS-068, and the line prints `unknown:` with a sentence naming that story rather than a zero (ADR-0044's third answer). The other four facts of the bullet are measured. |
| S2 | P3 | **dismissed** | six `sessions <status>` lines are the counts; ADR-0059 D3 argues why summing them into `live`/`stopped` would be a second definition of `Live` (the glossary's is three statuses) and would call an `error` row stopped. The words the bullet names are the six statuses plus the enum's own text. |
| S3 | P3 | **dismissed** | "networks" plural is met for the machine's own network; a session's `agents_<id>` network belongs to the row that describes it, is what the next boot's reconcile owns (ADR-0053), and removing it would destroy a live session's endpoint — ADR-0059 D6 records the choice and the `data: kept:` line says so. |
| S4 | P3 | **fixed** | `commands::logs` reads the config **only** in the `--session` arm, so a machine with a broken `config.toml` — the machine an operator runs `logs` on — still prints its unit's log. ADR-0059 D4 records the deliberate asymmetry. |

in `docs/notes.md` under this story's heading, because they are the shape of the next mistake rather than facts about
this one.
