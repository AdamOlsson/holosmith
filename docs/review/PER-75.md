## Review

### Correct (with evidence)

- **The keep-rule is where the branch is deleted, and it is provable without a daemon.** `Worktree::retained` (`crates/holosmith/src/worktree.rs:188-207`) answers the rule, `remove(&Retained)` (`:227-240`) is told what *not* to delete, and the six new `tests/worktree.rs` cases exercise it on real `TempDir` repositories. The `ahead == 0` arm is isolated by `a_branch_with_nothing_beyond_its_base_does_not_survive_a_delete` (repo on `trunk`, so "no target answers" would otherwise keep it) — the cross-rule agreement the notes landmine warns about is handled, not left to luck.
- **The three non-zero exits are read, not treated as failures** — `branch_head`/`merged_into`/`differing_ref` (`worktree.rs:270-345`), each matching the documented exit meanings, and none routed through `support::git` in a test.
- **The mutation claim in `docs/notes.md:1330-1334` holds.** Moving the `retained_for` call above the snapshot really does break `the_delete_answer_names_the_work_it_keeps_…`: in that test no wip ref exists before the snapshot, so `wip` would be `null`. The "after the snapshot, before the transition" placement (`crates/holosmith/src/http/sessions.rs:992-996`) matches ADR-0023's point-of-no-return split.
- **Judgement call 2 (the 202's shape) is right.** `Session` is untouched, so the three column-pinned tests (`crates/holosmith/src/sessions/mod.rs:201`, `tests/session_list.rs:26-118`, `tests/session_screen.rs:26-98`) and the 16-key body assertions (`tests/sessions_api.rs:486-490`, `src/http/sessions.rs:1417`) are unmoved; `DeleteAnswer` flattens (`http/sessions.rs:1044-1058`) and `assert_deleting` + `kept()` on the same response together prove `id`/`status`/`kept` are siblings, i.e. genuinely flattened, not wrapped. ADR-0038 is the right citation — it is the ADR that pins `Session` to fifteen keys and keeps `expected_stop` off the wire.
- **Judgement call 1 (`Retained::Unknown`) is on the right side of ADR-0023.** ADR-0023's "a failure leaves the row `deleting`" governs `SessionBackend::delete` failures — resources may still exist. A keep-rule failure leaves nothing behind and happens *before* the transition, so proceeding with `Retained::Unknown` strands no row; and the acceptance's bullet is a "kept when" (necessary) condition, so keeping the branch when the question cannot be asked is a superset in the safe direction. `?force=true` correctly does not change the rule (`tests/delete.rs` uses the unforced path; ADR-0052 §"`?force=true` forgives…").
- **The undo path is not a new data-loss hole.** `undo(Step::Worktree)` passing `Retained::nothing()` is safe because the provisioner only pushes `Step::Worktree` when `Provisioned::undoable()`, i.e. when this provision *created* the branch at base (`src/provisioner.rs:96-101`, `tests/worktree.rs`'s `a_later_step_failure_does_not_take_an_adopted_worktree_back`).

### Findings

1. **P2 — Standards (tests): the `kept: null` shape is claimed everywhere and produced by nothing.** `Kept::of` maps `Retained::Unknown → None` (`crates/holosmith/src/http/sessions.rs:1073-1085`) and `retained_for`'s error arm produces it (`:1019-1035`), but no test anywhere drives either: the only 202 assertions are the three-nulls case (`tests/delete.rs:231-235`, `scripts/verify.sh:3280-3286`, new test at `tests/delete.rs:262-280` which asserts three names), and `Retained::Unknown` appears in `tests/` only at `tests/worktree.rs:658` (backend level). `src/transcript.ts:558-560` and `web/test/transcript.test.ts:959-965` test the *renderer* for a shape the server is never proven to emit. Four documents assert the distinction as live: `docs/adr/0052-what-a-delete-keeps.md:96-99`, `docs/notes.md:1332-1335`, `docs/build.md:171-175`, `crates/holosmith/src/transcript.ts:558-559`. Fix (smallest): one `#[test]` beside `the_response_is_the_fifteen_column_names_plus_events` (`src/http/sessions.rs:1417`) asserting `serde_json::to_value(DeleteAnswer::of(session(), &Retained::Unknown))["kept"] == Null`, plus the `Retained::nothing()` counterpart — that also pins the 16-key total, which nothing does today (`assert_deleting` checks two keys and `kept()` one).

2. **P2 — Standards (tests): the egress stand-in now borrows the machine's own container name, so a failing run makes the test pass silently forever.** `tests/container.rs:986` (`let stand_in = PROXY_NAME;`), with the cleanup only on the last line (`:1053`). Any panic between `:990` and `:1053` — i.e. every assertion this test exists for — leaves a container named `hs_egress` running, and the guard at `:974-981` (`if docker.running(PROXY_NAME) { eprintln!("SKIP…"); return; }`) then returns *pass* on every subsequent run of the very test that was fixed for being unable to fail. It also poisons the baseline: `selftest::pair` treats `running(PROXY_NAME)` as "the machine's proxy" (`src/selftest.rs:236-251`) and would join and probe the stand-in; `tests/selftest.rs` then measures a `sleep infinity`. This is the exact failure mode `docs/notes.md:1348-1357` says HS-043 closed ("skipped whenever a proxy *was* running"), reached by a different door. Fix (smallest): hold the stand-in in a guard whose `Drop` calls `docker.remove_container(stand_in)` before any assertion runs. Related doc rot in the same block: `tests/container.rs:960-962` still says "The stand-in is `sleep infinity` in the same image under a name of its own — a test that ran under `hs_egress` would replace a live machine's proxy", directly contradicted by the paragraph added at `:966-971` ("the name the teardown **detaches** … the stand-in is `PROXY_NAME` now").

3. **P3 — Spec: `Retained::Unknown` gives one reason for two causes, and the wire/UI repeat the wrong one.** `Worktree::retained` returns `Unknown` when the *row* has no `base_commit` (`crates/holosmith/src/worktree.rs:192-193`) — a readable repository that answered nothing — while the variant's own doc says "The repository could not be read" (`worktree.rs:400-401`, and the enum doc at `:381`). Every downstream narrative repeats the narrower cause: `http/sessions.rs:1018` and `:1047`, `docs/adr/0052-what-a-delete-keeps.md:24-30`, `src/transcript.ts:558-559`. Reachable in production: `Provisioner::record` logs and carries on when `set_worktree` fails (`src/provisioner.rs:170-172`), so a row can reach `idle` (and later be deleted) with `base_commit = None`. Fix: one clause in the variant doc and in the ADR — "…or the row has no base commit to measure from" — or, better, a third variant if the distinction is worth the wire.

4. **P3 — Spec (UI): after `409 unsaved_work` the ordinary Delete button stays live beside "Delete anyway".** `web/src/main.ts:1075-1078` sets `say(...)` and unhides `forced`, but never hides `confirm` (or disables `yes`), so the operator sees two destructive buttons and the non-forcing one can only ever re-earn the same 409 (`send(false)`). Fix: hide `confirm` in that branch.

5. **P3 — Spec: the second keep-rule is implemented as "reported", not "kept".** `refs/holosmith/wip/<id>` is never deleted by the teardown (`worktree.rs:322-345` only *names* it), so a ref whose tree equals the branch's survives a delete unreported — reachable past a forced failed snapshot, where the pre-existing ref can equal `HEAD`'s tree. Bullet 3 says the ref "is kept when it differs from the branch", which makes the surviving-but-unnamed case outside what the bullet sanctions. ADR-0052 §"The wip ref … nothing deletes it" argues the choice, so this is a note, not a defect; the smallest honest option is one sentence in that section naming the force-path residue.

6. **P3 — Standards: the trait gained a method the conformance suite does not ask about.** `SessionBackend::retained` (`crates/holosmith/src/backend/mod.rs:337-345`) documents two backend promises ("a backend with no repository answers `Retained::nothing()`"), but `tests/backend_contract.rs`'s `conformance` (`:66-120`) has no case for it, though that file's own rule is "a case here is a promise the trait makes … the other backend is asked the same question" (`:4-6`). Both halves are covered elsewhere (`tests/delete.rs:231-235` for the stub, `tests/worktree.rs:697-716` for Docker-with-no-repository), so this is a missing case in the named home rather than a missing proof.

### Verdict

**OK with notes** — no P1: the keep-rule, its placement in the flow and the flattened 202 all hold up; the fix list is one small unit test for `kept: null`, one `Drop` guard in `tests/container.rs`, and three doc/UX touch-ups.
