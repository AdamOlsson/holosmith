## Spec axis

**Correct.** All five acceptance bullets are implemented and each has a reader: `container fake-pi` answers every command with the incoming id and replays HS-032's tool turn (`fake_pi.rs:130-190`, `tests/fake_pi.rs`); the fixture is committed with `{"type":"fixture","version":1,"schema":7,…}` against `SCHEMA_VERSION = 7` (`schema.rs:17`) with both header tests real; the smoke config is validated through the real parser and asserts port/roots/both prefixes (`smoke.rs:1130-1160`); the run creates → turns → asserts → deletes with 0/1/2 (`smoke.rs:120-160`, `commands/smoke.rs`); the docs say the dev instance does not cover Docker/git/proxy (`build.md` new section). `--version` really is measured through `agent::version_of`'s `--entrypoint pi … --version` (`agent.rs:726-736`), so D2's claim holds. `svc`/`container fake-pi` matches the spec's spelling (`HolosmithSpec.md:358`).

**Finding S1 — P1 — `execute`'s cleanup runs only on success.** `crates/holosmith/src/smoke.rs:404-410`: `let result = drive(&log, pid); let result = result.and_then(|id| …)`. `and_then` short-circuits on `Err`, so when `drive` fails — the *only* case a promotion cares about — `stop()` is never called, `remove_proxies()` and `gone()` never run, and the `std::process::Child` is dropped without a signal (std `Child` does not kill on drop). Net effect on the first bad candidate: the candidate's `serve` keeps running (holding its port and a DB whose root `finish()` then deletes underneath it), and `smoke_s_<id>`, `smoke_agents_<id>`, `smoke_hs_egress`, `smoke_hs_key` all stay on the machine. Contradicts `smoke.rs:302-303` ("Cleanup happens on **every** ending: a leftover container, network, proxy or root is itself a failure (`Failed`)") and ADR-0081's premise that this command can be trusted at a promotion. Gate arm 3 only exercises the success path, and the gate's `cleanup` trap masks the leftovers for the harness. *Smallest fix:* run the three cleanups unconditionally and merge their result — `let id = drive(...)`; `let cleanup = stop(&mut server).and_then(|()| remove_proxies(&docker)).and_then(|()| gone(&docker, &id?))`; return the `drive` error when it failed and the earlier failure otherwise (and make `stop` a `finally`, not part of the `Ok` branch).

**Finding S2 — P2 — arm 3's proxy-by-id check passes vacuously on this gate's own machine.** `scripts/verify.sh:11007` and `11029-11030`: `proxies_before`/`proxies_after` are `docker inspect --format '{{.Id}}' hs_egress hs_key 2>/dev/null || true`. In `serve_cases` the order is `case_server_images` → `case_build` → `case_smoke`, and `case_server_images` ends with `docker rm -f … hs_egress hs_key` (`verify.sh:10891`); `case_build` starts no server, so both strings are empty and `check "$name/machine_proxies" "" ""` passes. ADR-0081 D7 and `docs/notes.md` state this comparison as *the* proof that the machine's proxies are "the containers they were" — on the gate it measures nothing. (The case does still catch an unprefixed regression, via the `smoke: proxies: smoke_hs_egress, smoke_hs_key removed` line, because `removed_bounded` requires exit 0 — `docker.rs:278-283` — so that line proves both prefixed containers existed.) *Smallest fix:* assert non-vacuity — `[ -n "$proxies_before" ] || fail …` after `start_serve` in the case (or, cheaper, take a `note` and correct D7/notes to say what is measured).

**Finding S3 — P2 — an unremovable root is a note, not a failure.** `crates/holosmith/src/smoke.rs:928-940`: `finish` prints `smoke: root: … could not be removed` and the outcome stays `Passed` → exit 0. ADR-0081 D5 says the opposite in as many words ("an unremovable leftover is itself a failure rather than a note"), and `smoke.rs:302-303` lists the root. Also the config's own header comment (`smoke.rs:152`) says it is "removed with the run", which is false on every exit-1/2 ending — the gate's arm 2 *depends* on that falsehood (it greps the leftover config at `verify.sh:10977-10990`). *Smallest fix:* `fn finish(root: &Path) -> Option<String>` folded into the ending, and reword both comment and D5 to state that the config survives a refusal on purpose.

**Finding S4 — P2 — the composers are tested; the four readers that feed them are not.** The prefix claims are proved on the *functions*: `container.rs:807-833`, `container.rs:838-872`, `selftest.rs:499-515`, `reconcile.rs:613-638`. Nothing proves a caller passes the right string:
- `commands/serve.rs:164-167` — replace both arguments with `""`; every `cargo test` stays green and `case_smoke` arm 3 still passes, because the smoke boot's `pair()`/`key_pair()` are skipped when the machine's proxies are gone.
- `doctor.rs:248` — same mutation, same result.
- `reconcile.rs:294-295` — mutate `container_listing_prefix(&config.container_prefix)` to `config.container_prefix.clone()`; the smoke boot then never sweeps its own `smoke_s_*` leftovers and no test notices (the unit test passes the composed prefix in itself).
- `commands/serve.rs:505-509` (preview) — this is exactly the defect b798d55 fixed ("a double-composed prefix the preview listener showed as a 502"), and the fix landed with **no test**, so it can return silently: the smoke run never touches the preview listener.
- `uninstall.rs:723-724,739` — the comment at 720-722 says composing twice "is the defect **this test** exists for"; there is no such test (grep: no `container_prefix`/`smoke_`/`s_s_` in `uninstall.rs` or `crates/holosmith/tests` outside `container.rs`'s and `reconcile.rs`'s unit tests).
*Smallest fix:* one unit assertion per reader, cheapest first — `Reconciler::new(…)`'s two fields for a `smoke_` config; `selftest::Names::of(&Config)` instead of two `&str`s (which also kills the swap hazard: `of(&config.network_prefix, &config.container_prefix)` compiles and is invisible whenever both prefixes are equal); and a `preview::Containers` test asserting `container_name`'s input is the raw prefix.

**Could not verify without running:** `cargo test`/`clippy`/`fmt`, `scripts/verify.sh` (93→97 cases?), the real arm 3, the note's "14 events with one `message.delta`" count, and that `docker rm -f <missing>` exits non-zero (read `removed_bounded`, not measured).

## Standards axis

**Correct.** One composer per kind, doc comments that name the reason the prefix is load-bearing, the gate case with no `SKIP` and three arms (deleting the verb/fixture/config fails arms 1–2 on any machine — the "SKIP fires when the feature is deleted" trap is avoided), the fixture's two tests, the `list_prefix` composition in one function, and the `Backends::Docker` boxing with the `large_enum_variant` reason recorded in `notes.md`.

- **T1 — P2 — a production sentence left on the constant.** `selftest.rs:433-439`: `decide`'s leak finding formats `crate::container::PROXY_NAME`, so a smoke boot that measures a leak tells the operator to look at `hs_egress` when its own proxy is `smoke_hs_egress`. The diff rewrote `pair`/`key_pair` to take `Names` and left `decide` (pure function, called from `run_with`). ADR D5: "every reader uses it". *Fix:* pass the egress name into `decide` (or take `&Names`), and add the `smoke_` arm to `selftest.rs:781`.
- **T2 — P3 — `container.rs:101-103` orphaned paragraph.** `network_name`'s doc now opens with "The command the container runs is pi's RPC loop … this constant is what replaced that placeholder", a sentence about a different item. The hunk rewrote this doc block and kept it. *Fix:* delete the two lines.
- **T3 — P3 — two spellings of the image name.** `smoke.rs:46 pub const IMAGE_NAME` has no reader (only the declaration); `images.rs:47-49` spells `"holosmith-smoke"` itself while claiming "one spelling for `images` and `smoke`". *Fix:* `format!("{}:{}", IMAGE_NAME, env!(…))` in `images::smoke_image()`, or drop the const.
- **T4 — P3 — second composition inside the file that owns the composer.** `smoke.rs:891-892`: `format!("{PREFIX}{}", container_name("", id))` / `network_name("", id)` — equivalent to `container_name(PREFIX, id)`, which `remove_proxies` two functions down does use. *Fix:* call the composer with `PREFIX`.
- **T5 — P3 — `tests/fake_pi.rs:6` "a fake that **danied** a wire"; `tests/fake_pi.rs:281` `let _ = AgentError::Closed;`** (a no-op statement keeping an unused import alive). *Fix:* reword; drop the import and the statement.
- **T6 — P3 — Middle Man.** `smoke.rs:1286-1288 recipe_label_for` only calls `recipe`, and its doc ("named so the test does not reach into `recipe`'s byte layout") is false — the test then calls `recipe_label_for`. *Fix:* call `recipe` directly.
- **T7 — P3 — the avoided spelling.** GLOSSARY's **Smoke run** says `_Avoid_: Smoke test (that is the step, not the command)`, and the diff introduces "the smoke test" *for the command* at `cli.rs:89` and `commands/smoke.rs:1`. *Fix:* "the smoke run" in both.
- Baseline judgement calls, no fix demanded: **Data Clumps** — `(container_prefix, network_prefix)` travel as two sibling `String`s into `ContainerSettings`, `SessionContainer`, `Reconciler`, `preview::Containers`, `Names::of` and `uninstall::sweep`; one small type would make S4's swap hazard unrepresentable. **Speculative generality** — `Header.turn`/`recorded` and `FIXTURE_VERSION` are read only by tests (ADR D3 justifies them as documentation).

**Merge verdict: BLOCK** — S1 (and its doc contradiction S3) must be fixed before this is what `upgrade` branches on; S2 should be fixed or the claim withdrawn, because a hollow gate assertion plus an ADR that cites it is the pattern this repo keeps re-finding.
