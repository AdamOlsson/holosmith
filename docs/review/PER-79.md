## Review

Read-only: nothing was edited, and no command that changes the tree was run. Sources: `/tmp/holosmith/reviews/PER-79-diff.txt`, the files at HEAD `2fc3aa5`, and the spec/story/ADR/gate sources the brief names.

### Spec axis

- **P2** — `crates/holosmith/src/commands/deploy.rs:56-58,73-82` (`resume`). A **failed dry run prints a resume command that is not the command that just ran**: `resume()` emits only `--config`/`--root` and never `--dry-run`, so `server deploy --dry-run` on a machine whose step 4 fails prints `deploy: resume: holosmith server deploy …`, which pasting installs step 2 for real. ADR-0056's own justification is "the resume is **the command that just ran**", and the CLI help says `--dry-run` "change[s] nothing". Untested: `tests/deploy.rs::a_failing_preflight_stops_at_step_one` calls `deploy::run`, not the command, and asserts nothing about the resume; the gate only exercises the non-dry resume. *Change:* `if args.dry_run { command.push_str(" --dry-run") }`, and assert the line in one test.
- **P2** — `crates/holosmith/src/deploy.rs:668-676` (`install`'s `satisfied`/`changed` sentences). **Step 2 reports `satisfied` over a body that is only 3 of the spec's 5 items**: item 10 step 2 also asks for the `holosmith` service user (in the docker group) and the VAPID keys, which ADR-0056 hands to HS-049; nothing in the output says so, so "all 6 paths are present with their modes" reads as the step being done, and the operator's only cue is the summary's `4 of 7` — which counts steps 3,5,6,7 and never mentions step 2. That is the same "a step that read part of itself and reports a pass" shape the ADR forbids for skipped steps. *Change:* a `STEP2_REMAINDER` remark appended to step 2's sentence (mirroring `HELD_PORT`): `; the service user and the VAPID keys are HS-049's`.
- **P2** — `crates/holosmith/src/deploy.rs:614-620` (`preflight`) with `crates/holosmith/src/preflight.rs:511-521` (`disk`). **On a fresh host — the deploy's whole purpose — `min_free_gb` is never evaluated.** `preflight::disk` answers `Unknown` when `data_root` does not exist (its doc comment even names "`server deploy` runs before step 2 has created anything"), and `deploy::preflight` only fails on `Outcome::Fail`, so step 1 says `satisfied` with `1 unknown (disk)` and step 2 then creates the data root with no second read. The second run does measure it (the root exists by then), so the gap is exactly the run that matters, and HS-048's image builds (GBs, step 3) will run behind an unmeasured floor. *Change:* after step 2's apply, re-ask the disk finding against the now-existing data root and fold a failure into step 2's line (or a fifth step-1 sentence saying the floor is unmeasured until the tree exists).
- **P2** — `crates/holosmith/src/deploy.rs:839` (`apply`). **`sudo` can never prompt**, so acceptance bullet 5 holds only where the credential is already cached or NOPASSWD: `Command::output()` gives the child `Stdio::null()` for stdin, so `sudo install …` on a normal machine fails with `sudo: a terminal is required to read the password` and the printed resume repeats it. ADR-0056 covers only "A missing `sudo` is a step failure". *Change:* `.stdin(Stdio::inherit())` on the child (or one `sudo -v` before the first write), and say so in the ADR.
- **P2 (record, don't re-decide)** — `docs/adr/0056-…md` (whole file). The **exit code** decision — "0 with an `incomplete` line while 4 of 7 steps are unbuilt" — is recorded only in `docs/notes.md`'s landmine list, not in the ADR, yet RESUME §7 says almost every hard-to-reverse decision is an ADR and a later reader will "fix" this one. *Change:* one paragraph in ADR-0056 stating exit 1 iff a step **failed**, and why.
- **nit** — `crates/holosmith/src/commands/deploy.rs:60`. The tail prints `control_origin`, which is `http://localhost:8080` unless the operator set the key; the gate's `^deploy: url: http` passes on that default (`deploy_config()` in `scripts/verify.sh` sets no `control_origin`), so neither the code nor the gate can tell "the URL this machine will serve" from a built-in default. *Change:* when `control_origin` is the default, say so on the line (or print the origin `control_listen` implies).

### Standards axis

- **P2** — `docs/build.md:525-528`. **"The gate needs neither" is false.** `scripts/verify.sh:5460` runs `cargo test` as a gate phase, and `crates/holosmith/tests/deploy.rs:94-96` hard-codes `/usr/bin/install`, `/usr/bin/chmod`, `/usr/bin/sudo`, driving the first two for real (the module docs say so at `tests/deploy.rs:10-11`). On a host where coreutils is not at those paths the tests **fail**, where the repo's convention (`docs/build.md`'s prerequisites, `tests/config/mod.rs`'s `SKIP: … exists on this machine`) is to print one line and skip. *Change:* "the gate's *case* needs neither; `tests/deploy.rs` runs the host's `/usr/bin/install` and `/usr/bin/chmod` (measured present), and prints one skip line where they are not" — plus the skip.
- **P2** — `docs/adr/0056-…md:28`. "**Three** of the seven steps have no body in this release — step 3's … and steps 5 and 6" contradicts the next paragraph ("**Step 7 is HS-049's entirely**"), `deploy.rs:33` ("Four of the seven"), the report's `4 of 7`, and the gate's `incomplete: 4 of 7`. *Change:* "Four".
- **nit** — `crates/holosmith/src/proxies.rs:45-49`. `NAMES`' doc says "three readers ask for them by name: `uninstall`, `doctor`'s two proxy findings and this module"; the only user is `running()` (`proxies.rs:195`) — `doctor`/`uninstall` use `container::PROXY_NAME`/`key::KEY_PROXY_NAME`. *Change:* drop the claim, or use `NAMES` in those readers.
- **nit** — `crates/holosmith/src/deploy.rs:383-386`. `Target::secrets_dir` has no caller anywhere in the crate (only its own body), while `items()` recomputes `config.data_root.join(key::SECRETS_DIR)` — one dead path builder and a second spelling of the same join. *Change:* delete it, or call it from `Target::config`/`items`.
- **nit** — `crates/holosmith/src/deploy.rs:902-906` + `:869-890` (`staging_dir`/`stage`). The staging directory is a predictable `/tmp/holosmith-deploy-<pid>` and `stage()` writes into it with `std::fs::write`, which follows a symlink; because the system-path run is a **sudo** run, a pre-created `/tmp/holosmith-deploy-<pid>/config.toml → /etc/…` entry is an arbitrary root-owned write in the window after `remove_dir_all`. *Change:* create the staged file with `OpenOptions::new().write(true).create_new(true)` (fails on an existing entry, symlink included), or give the directory a random suffix.
- **nit** — `crates/holosmith/src/deploy.rs:409` + `Report.target`. The field is computed, carried and asserted by `tests/deploy.rs`, but neither `render()` nor `commands::deploy` prints it, so no output line says which tree was installed (the operator must read step 2's paths) and the gate never checks it. *Change:* put it in the header (`deploy: run (into …)`) or drop the field.
- **nit** — `docs/notes.md` (new HS-047 landmine on `find | stat`). It says the listing and the two `cmp`s are "what 'changed nothing' means"; a second run that re-installed identical bytes passes both and is caught only by the `satisfied` grep. *Change:* name that third detector, so a later author does not delete the word assertion as redundant.

### Confirmed correct (evidence)

The seven steps, their numbers and their five words are the spec's (`DeployStep::ALL`/`number`/`word`, asserted in `tests/deploy.rs::the_seven_steps_are_the_specs_order` and greped by `case_server_deploy`); **a `skipped` step never reads as satisfied** — it carries its owner (`deploy.rs:33-45`) and the summary counts it (`deploy.rs:244`), and the gate greps `HS-048`/`HS-049` per step; "the second run changes nothing" is a **real assertion**, not silence (`scripts/verify.sh`: `deploy_listing` diff, `cmp` of `config.toml` *and* `keys.toml`, `satisfied` on steps 1/2/4); **no config key was added** — `config/mod.rs`, `config/render.rs`'s `KNOWN_KEYS`, `config/schema.rs` and the golden file are untouched by the diff; **`docs/stories/**` was not edited** apart from the ADR index line in `docs/stories/README.md` (RESUME §7: "one line each in `docs/stories/README.md`") and the count 55→56, which matches the 56 ADRs now on disk; **one `case_*` per story**, added to `serve_cases` and placed before `case_doctor_full` as the notes require; **neither gate half skips on the bug it exists to catch** — the offline half's three runs still produce their verdicts with no `docker` CLI (step 4 fails either way), and the second-run claim is proven daemon-free in `tests/deploy.rs`; `keys.toml` is never installed over (`Kind::Kept` → `Action::Mode`, with a test that writes real key bytes and a wrong mode and asserts both), and `--root` prefixes once, asymmetrically, exactly as documented.

### Merge verdict

**FIX-THEN-SHIP.** The design is sound and its hardest claims are actually asserted, but two allowed-to-merge items deserve a commit: the dry-run resume that would install on a machine the operator only asked to inspect (`commands/deploy.rs:56-82`, currently untested), and step 2 reporting a pass over the half of the spec's step 2 that HS-049 still owns. `docs/build.md:527` and ADR-0056:28 ("Three" vs four) are one-line corrections in the same change, since both are contradicted by code this diff adds. The fresh-host `min_free_gb` gap and the un-promptable `sudo` are the two I would raise to P1 before HS-048 lands image builds behind them. I could not run the gate; the supervisor must run `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test` (with `tests/deploy.rs`'s `/usr/bin/install` requirement in mind) and `scripts/verify.sh`.
