## Standards

- **Correct** — the lock rule holds by construction: `provisioner.rs:150-186` (`set_status`) takes `Arc<Mutex<Database>>`, issues one synchronous `sessions().set_status(...)` and returns a `bool`; no guard exists in any `async fn`, so `MutexGuard: !Send` keeps the compiler's guarantee that ADR-0012/0013 describe. The event path is the writer only (`provisioner.rs:203-226` → `EventWriter::append`, `events/mod.rs:82-87`); the provisioner never touches SQL or the log table, so the repository-owns-its-SQL rule and the one-writer rule are intact. Broadcast-after-commit is untouched.
- **Correct** — the payload has one spelling for the four words: `Step` is a hand-written `Serialize` through `Step::as_str` (`backend/mod.rs:44-84`), not a `rename_all` derive, matching the `Status` precedent (`sessions/mod.rs:70-76`); `StatusPayload` is one struct with explicit `Option` fields and a unit test pinning the exact three keys and nulls (`provisioner.rs:230-253`). `Status` reuses `as_str` for the wire word.
- **Correct** — `AppState::provisioner()` (`http/app.rs:58-70`) is the one wiring point; no `Router` accessor was added and `Routes`/`App` are untouched. The only three `AppState` constructions (`commands/serve.rs:127`, `tests/support/mod.rs:95,135`) all set `backend`, so the new field cannot be forgotten silently.
- **Correct** — config plumbing follows ADR-0006's six edits: field `config/mod.rs:180-184`, `KeySpec` row `config/schema.rs:73-78`, setter `:455-462`, rule test `backend_must_be_stub_or_docker` (`:1096-1105`), count bumped to 26 (`:702`), golden `tests/golden/config-default.toml:2`. `render` reads the value through `serde_json::to_value` → `Value::String`, so `config show` emits `backend = "docker"` byte-identically to the golden, and the belt (`config/mod.rs:452-464`) is skipped when the setter already reported a problem, which is what makes the one-problem expectation in the new test reachable.
- **Correct** — test hygiene: every new test has its own `TempDir` label ("provisioning-steps", "-stream", "-handoff", "-idempotent", "-failure", "-docker", "-disk"), so exactly one `Database::open` per path per process; `SPATIENCE`/`SLOW_STUB_STEP` (60 s) removes the race the new background task would otherwise create for tests that read a row immediately (`tests/support/mod.rs:104-122`), and no `unwrap()` was added (all `expect`/`PoisonError::into_inner`).
- **Correct** — the gate grew as `docs/build.md:130-132` demands: two `case_*` functions plus their `serve_cases` entries (`scripts/verify.sh:276-277,535-566`), and `docs/build.md:95-121` documents both. The `fetch_sse_until` needle-and-bail design (`verify.sh:213-241`) is bounded in both directions (3 s per line, 200 lines) and the `/dev/tcp` path is quoted like its siblings.

- **should-fix** — `docs/stories/README.md:129-131` adds three ADR bullets whose link targets do not exist. The files are `0011-session-row-id-and-absent-status-check.md`, `0012-create-endpoint-shared-connection-and-cap-refusal.md`, `0013-event-log-single-writer-and-seq-counter.md`; the bullets point at `0011-session-identity-and-status-as-an-enum.md`, `0012-create-endpoint-lock-shape-and-validation-precedence.md`, `0013-one-writer-thread-for-the-event-log.md`. Only 0014 and 0015 match. No gate checks links, so this ships broken. Fix: correct the three filenames (the bullet *text* for 0011 and 0012 matches those ADRs' content — `0011:1-10` lists the six statuses and the id rule, `0012:1-6` the shared connection and the cap).

- **should-fix** — `GLOSSARY.md:133-138`, the new **Step** entry, states a rule the failure path breaks and uses its own forbidden synonym. "the last event of a provisioning carries `null` because no step is running then" is false when a provisioning fails: `provisioner.rs:154-159` announces `Some(step), Status::Error`, and `tests/provisioning.rs` (`a_failure_at_a_named_step_undoes_what_completed_and_ends_error`) asserts `["worktree","network","container","container"]` and `last["step"] == "container"` — which is also what ADR-0015 records ("on a failure it names the step that failed"). Second, the definition opens "One of the four **stages** of provisioning" while its own `_Avoid_: Phase, stage, task, milestone` forbids that word. Fix: "…the terminal event of a successful provisioning carries `null`; the terminal event of a failed one names the step that failed" and "One of the four steps of provisioning".

- **should-fix (latent, no observable impact today)** — `commands/serve.rs:82` resolves `--backend` but never applies it to the loaded config, so `AppState.config.backend` (built at `:127-134`) keeps the *file's* value while `runtime.backend` holds the flag's. ADR-0006 is explicit: "Precedence is `defaults < file < CLI key overrides`; the overrides (`--port`, `--data-dir`, `--backend`) … are applied to the loaded value". Nothing reads `state.config.backend` today (the banner prints `runtime.backend`, `commands/serve.rs:200-204`; health carries no backend), so nothing is observably wrong — but this is exactly the second-source-of-truth trap a later handler (HS-013/HS-024) would fall into. Smallest fix: `loaded.config.backend = backend;` immediately after `:82` (`loaded` is already `mut`).

- **nit** — `commands/serve.rs:198-206` and `http/sessions.rs:197-206` (and ADR-0015, "spawns it after the row is committed and after the response is built") all say the answer is built before the handoff; the code spawns first and calls `created(session)` second. Harmless — the task gets a clone taken before it starts, so the 202 body is always `starting` — but the prose is wrong. Fix: swap the two statements (or the sentence).

- **nit** — `scripts/verify.sh:540` reads the banner positionally (`sed -n '2s/…' "$WORK/serve.err"`), while every other banner read in the file anchors on the line's leading word (`grep -m1 '^database '` `:309`, `sed -n 's/^control_listen //p'` `:595`, `:599`). It works only because `banner()` prints `log …` first (`commands/serve.rs:190-204`); a banner line added above the role line turns this case into a confusing `expected 'stub', got ''`. Fix: `sed -n 's/^holosmith .* backend \([a-z]*\)$/\1/p' | sed -n '1p'`, matching `docs/build.md:94-95` ("read from the startup banner, never assumed").

- **nit** — `backend/mod.rs:138` says "The nine operations the story names, plus the per-step undo", and ADR-0015 says "A tenth method, `undo`". HS-011's line names eight (provision, start turn, steer, abort, stop, resume, delete, snapshot) and the trait has nine methods total. One word each.

- **nit** — `backend/mod.rs:100-113`, `BackendError::unsupported` does `Box::leak(format!(…))` on every call, and its comment claims the opposite ("rather than an allocation this path takes every time"). Currently unreachable — `DockerBackend::provision` uses `unsupported_step` with a `&'static` literal (`backend/docker.rs:36-41`), and nothing calls the seven lifecycle methods until HS-012+/HS-019+. Still an unbounded leak the day an endpoint does. Smallest fix: `detail: Cow<'static, str>` with `Cow::Owned(format!(…))` (`BackendError` is `Clone + PartialEq`, so the derive still holds); no new crate.

- **nit** — `config/schema.rs:455-462` hand-lists `[Backend::Stub, Backend::Docker]` and repeats the two words in the message, where the sibling `Role` keeps one `WORDS` table for parse and print (`config/mod.rs:44-52`). The new `runtime.rs` test pins the *serde* round-trip, not this array, so a third variant would be accepted by `--backend` and refused by the file. A `Backend::ALL`/`WORDS` const would restore the one-spelling rule.

- **nit** — `runtime.rs:1-6` still frames the module as "What this run is, as opposed to what the machine is configured to be", and `GLOSSARY.md:140-143` says "`runtime::Backend` is only which backend this run chose". Both are now partial: `Config.backend: Backend` (`config/mod.rs:180-184`) makes the same type the machine's setting. Nothing is literally false about `Runtime`, but a reader landing here will not learn the file names a backend too.

- **nit** — `tests/support/mod.rs:22` places `use std::time::Instant;` below the `holosmith::` imports, breaking the file's std-first grouping (harmless to `rustfmt`/`clippy`, just drift in a block the same diff otherwise kept ordered).

## Spec

Acceptance items judged against the code, not the ADR:

- **Verified — item 1.** `backend/mod.rs:130-186`: `SessionBackend` covers provision, start turn, steer, abort, stop, resume, delete, snapshot, plus the decided `undo`. `StubBackend` implements all of it and creates nothing (`backend/stub.rs:130-200`); the delay is a constructor argument (`StubBackend::new`, `:76-84`, `DEFAULT_STEP_DELAY` 200 ms) and a test pins it (`a_step_takes_the_delay_it_was_built_with`). Caveat by decision, not by defect: the delay is per-stub, applied to every step, not four separately configurable delays.
- **Verified — item 2.** Config: `KeySpec { path: "backend" }` + `set_backend` accepting exactly the two words, with `backend_must_be_stub_or_docker` refusing `"Podman"`; `--backend` is `Option<Backend>` (`cli.rs:30-32`), resolved at `serve.rs:82`; `tests/serve_cli.rs` covers file-wins-with-no-flag, flag-overrides-file, and default-is-docker from the real binary's banner; `scripts/verify.sh:538-542` proves the config half on the shipped artifact. The stub needs no Docker, git or agent: `backend/stub.rs` imports nothing but `std`/`tokio::time` and records calls.
- **Verified — item 3.** `Provisioner::spawn` is `tokio::spawn`, called only from the handler (`sessions.rs:203`), never awaited; `run` walks `Step::ALL` and announces `Some(step)` before each step (`provisioner.rs:96-101`), so a browser sees `worktree, network, container, pi` then the terminal event — pinned by `tests/provisioning.rs::a_create_provisions_the_four_steps_in_order_and_ends_idle` (log) and `the_steps_reach_a_browser_over_the_event_stream` (SSE, seqs 1-5).
- **Verified with one honest limit — item 4.** `run`'s error arm collects the completed steps, undoes them in reverse, then writes `error` + `status_reason` before announcing it (`provisioner.rs:102-118,144-160`); `a_failure_at_a_named_step_undoes_what_completed_and_ends_error` proves the undo order `[Network, Worktree]`, the four events, and the row/event agreement on the reason. "Partial resources are not left behind" is provable only in the stub's cheap form (`provisioning_leaves_nothing_on_disk`): the stub creates nothing, and the real teardown is HS-024's — which ADR-0015 states. The undo is best-effort by decision (a failed undo is logged, the rest still run).
- **Verified — item 5.** `settle` writes `Idle` before the event and `run` returns only after it (`provisioner.rs:132-141`); the test asserts `row.status == Idle`, `status_reason == None`, `worktree == ""`.
- **Verified — item 6.** `StubBackend::failing_at(step)` (`backend/stub.rs:86-97`) plus `a_failure_at_a_named_step_undoes_what_completed_and_ends_error`, and the unit test that the named step fails while the others do not.
- **Verified — HS-012 boundary.** No transition table, no `from`/`to`; exactly two transitions through the pre-existing repository writer (`sessions/repository.rs:147-157`), and `Status` keeps all six spec states.
- **Not verified (needs a running binary / the gates)** — the demo itself ("create a session and watch `worktree, network, container, pi` arrive, then `idle`") under `serve --backend stub` at 200 ms; whether `case_provisioning_steps` really reads the five events on a live boot (my reading of `verify.sh:213-241,519-527` says the replay-from-zero stream carries them and `grep -o '"step":"[a-z]*"'` yields the four words, but that is a reasoning claim, not an observation); ADR-0015's "19 cases, 56 assertions"; and that the crate compiles (notably that `#[allow(async_fn_in_trait)]` is the only lint suppression needed and the `tokio::spawn`'d future is `Send`). Commands a supervisor must run: `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`, `scripts/verify.sh`.
- **note** — the payload's terminal *success* event is `step: null` as decided, but the terminal *failure* event carries the failed step (ADR-0015; code at `provisioner.rs:158`). That is coherent and deliberate; the only defect is that GLOSSARY states the rule without the exception (Standards, GLOSSARY finding).
