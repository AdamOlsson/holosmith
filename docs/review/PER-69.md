# Code review — PER-69 / HS-037 (the egress proxy), `ef27504..HEAD`

## Review

Scope note: reviewed `ef27504...HEAD` from `/tmp/holosmith/reviews/PER-69-diff.txt` plus the tree. The tree carries **one hunk not in the diff artifact** — `crates/holosmith/src/commands/serve.rs:306-318` (the `!proxy.binary.is_file()` guard, ADR-0035) — so that guard is reviewed from the tree, not the diff.

### Correct (verified by reading)

- `hs_egress` run vector (`container.rs:517-596`): `--detach --name hs_egress --network egress --restart unless-stopped --cap-drop ALL --security-opt no-new-privileges -v <binary>:<binary>:ro --entrypoint <binary> <agent_image> proxy egress --listen 0.0.0.0:3128 --allow …`, one `-v`, no data/projects/socket mount. Satisfies acceptance 1's container/network/restart clause and ADR-0045's verbatim vector.
- Port rule before resolution: `Rules::target` (`egress.rs:264-285`) → 405 `NotTunnel`, 400 `Malformed`, 403 `NotTls`, 403 `NotListed`; non-listed names are refused **without any lookup**, so no DNS-based exfiltration.
- Address rule (`egress.rs:314-360`): loopback, unspecified, 169.254/16, 10/8, 172.16/12, 192.168/16, 100.64/10, `fe80::/10`, `fc00::/7`, and `to_ipv4_mapped()` judged as IPv4. *Every* answer is checked before `connect` (`egress.rs:481-499`), and `connect` uses the checked list, so there is no re-resolve window.
- Attribution: `proxy_url` (`container.rs:81-83`) → `http://<id>@egress-proxy:3128`; username extracted from `Proxy-Authorization: Basic` and validated with `tool::valid_id` before it can reach a log line (`egress.rs:118-131`); empty password, `NO_PROXY=key-proxy` pre-exists (`agent.rs:75`). Literal acceptance string deviates exactly as plan decision 5 says, and the test pins it (`container.rs:779-780`).
- Teardown order: leave-then-`network rm` in `remove_network` (`backend/docker.rs:619-643`), and `join_network`'s disconnect-first makes resume idempotent (`docker.rs:232-244`).
- Nothing widens reach: for `network=false` `apply_proxy` detaches (`backend/docker.rs:354-366`); the only new endpoint on a session network is the proxy, and every non-public destination it is asked for is refused.
- ADR/README hygiene: 45 ADR files match `docs/stories/README.md`'s "Forty-five", ADR-0045 registered, gate case added to `serve_cases` (`scripts/verify.sh:347`) with a correct assertion count (4 `check`s + 3 greps).

### Standards

- **Finding: P1** — the proxy start is an **unbounded `docker run` on the pre-bind startup path**, which the repo forbids for exactly this call shape. `serve.rs:127` → `serve.rs:298-320` (`docker.remove_container` + `docker.run_detached`) → `docker.rs:255-258` → `docker.rs:70-88` (`Command::output()`, no deadline). `docker.rs:141-155` documents the rule it breaks: *"Bounded, unlike every other call here, because this one runs on the startup path: a daemon that accepts a `docker run` and then wedges would otherwise hang the boot before the listener binds."* The listener binds later, in `run`'s `body` (`serve.rs:~236`). Because `hs_egress` runs `agent_image`, a machine where that image is absent **pulls** here — and docs/build.md's own supported case ("a machine whose image is not built yet must still serve the UI that says so"; ADR-0044's `Unknown`) becomes a boot that blocks on a registry or a wedged daemon. Smallest fix: run the proxy start through `Docker::attempt`'s bounded pattern (or spawn it as a task after the listener binds), and cover `remove_container` on the same path.
- **Finding: P2** — `apply_proxy` mutates a network endpoint outside the per-session start lock. `provision_network` (`backend/docker.rs:323-337`) has no `start_lock`, while `delete` (`:862`), `resume` (`:832`) and `provision_container` (`:405`) all do, and `delete`'s own comment (`:859-861`) names the race. A delete that lands between `provision_network`'s join and `remove_network`'s rm re-attaches the proxy after the leave, so `network rm` fails → one `warn` and an orphan `agents_<id>` with a dangling endpoint (HS-044 territory, but newly reachable). Smallest fix: take `self.start_lock(&session.id)` in `provision_network`, as `provision_container` does.
- **Finding: P2** — the daemon-gated test hijacks the machine-wide production container name. `tests/container.rs:957` and `:1017` `docker.remove_container(PROXY_NAME)` and `:967-968` create a `sleep infinity` stand-in **under `hs_egress`**, so running `cargo test` on a machine with a live `serve` destroys the operator's egress proxy and leaves it absent until the next boot (sessions lose internet until then). Smallest fix: use a test-only name (`hs_egress_test`) for the stand-in, and gate on `docker.running(PROXY_NAME)` → `SKIP` — which also gives the newly added `Docker::running` (`docker.rs:261`, **no caller anywhere**) its intended use.
- **Finding: P2** — the new test does not exercise the seam it exists to justify. `tests/container.rs:988-1014` calls `docker.join_network` / `docker.leave_network` directly; deleting the leave from `DockerBackend::remove_network` (`backend/docker.rs:624-640`) would leave this test green. Nothing in the tree tests the backend's leave-then-rm (the only other caller, `backend/docker.rs:1176`, asserts `Ok`). Smallest fix: assert the order through `backend.undo(&session, Step::Network)` / `delete` on a network with the stand-in attached.
- **Finding: P3** — `Rules::allow` (`egress.rs:246`) is the one new public item with no doc comment, against the house style every neighbouring item follows.
- **Finding: P3** — `egress.rs:401` says "Serve until the listener fails", but the loop never returns on failure: it warns and sleeps 100 ms (`egress.rs:424-436`), i.e. ~600 warn lines/minute on a permanently broken listener, which is the noise the comment claims to avoid. Fix the doc, and back off (or log once).
- **Finding: P3** — `Rules::new`'s doc (`egress.rs:230-231`) claims `Crates.IO` is "the same rule the config pass already validated as one domain"; the config pass *rejects* uppercase (`config/mod.rs:897`), so the lowercasing only ever covers `--allow` given on the command line. Reword to "the flag is normalised; the config pass already refused this spelling".
- **Finding: P3** — `container.rs:508-509` says "[`crate::docker`]'s `connect` is what joins them"; there is no `docker::connect`, it is `join_network`. Fix the sentence (and `:515`'s "the one field (`ContainerSettings`) that names both" reads as if `EgressProxy` had a `ContainerSettings`).
- **Finding: P3** — `remove_network`'s leave arm (`backend/docker.rs:624-640`) discards `leave_network`'s `bool` (`; Ok(())`), so its only reachable `Err` is a `JoinError` — yet the message says "the egress proxy could not be detached … the removal below is still the one that decides", which that path can never mean. Log the `bool` at `debug` or reword.
- **Finding: P3** — `docs/build.md:227-235`: the insertion leaves the paragraph broken — `ADR-0045).` alone on a line, then `A case that` / `must assert` / `one code keeps…`. Rejoin the wrapped sentence ("… would need the internet (ADR-0045). A case that must assert one code keeps…").
- **Standards verdict: OK with notes** — no gate violation found by reading (edition 2024 so the let-chain in `connect` is legal; no `unwrap` in non-test code; doc/gate/assertion conventions followed); the P1 is a violation of the repo's own bounded-startup rule.

### Spec

- **Finding: P2** — acceptance bullet 5's "logs … bytes" is lost precisely when it matters: `egress.rs:504-508` returns without any record if the `200 Connection Established` write fails, and `copy_bidirectional`'s `Err` is flattened to `(0, 0)` by `unwrap_or`, so a tunnel that carried megabytes and then died logs `status=allowed bytes_up=0 bytes_down=0`. Two smaller members of the same gap: a 400 (unreadable or unparseable head) writes no record at all, though ADR-0045 says "the refusal is the interesting part". Smallest fix: split the socket (`tokio::io::split`) and `join!` two `tokio::io::copy` futures from a pair of counters, so the counts survive an error; log a `Refusal`-shaped record for the 400 paths.
- **Finding: P2** — ADR-0045 does not discharge the decision ADR-0044 handed it. ADR-0044 ("One probe, two networks, one distinction") records that a session container **can** reach anything the host binds to `0.0.0.0` at its own network's bridge address — the control listener included — and says "closing the gap … is a decision HS-037 or the phase-1 verification run owns". ADR-0045's "What is left, on purpose" is silent on it; it only refuses such destinations *inside* the proxy ("the proxy's half"). Nothing in the story closes or re-delegates it. Smallest fix: one bullet in ADR-0045's "What is left" naming the owner (phase-1 verification / HS-046), so the 0044 hand-over is discharged rather than dropped.
- **Finding: P3** — `address_problem` (`egress.rs:314-360`) covers the four named ranges plus mapped/unique-local, but not the other IPv6 spellings of a v4 destination: 6to4 `2002::/16`, NAT64 `64:ff9b::/96`, IPv4-compatible `::a.b.c.d`, and site-local `fec0::/10`. ADR-0045 claims "the IPv6 equivalents", and the check's stated purpose is a *hostile* allow-listed name's DNS, so on a host with those routes `CONNECT <listed>:443` resolving to `64:ff9b::7f00:1` reaches loopback. Three lines: match the three prefixes and recurse on the embedded v4.
- **Finding: P3** — GLOSSARY `Allow-list` states as fact that it "never contains a provider host"; nothing refuses one (`domain_problem` cannot tell a provider host from any other name, and the proxy would tunnel to it). Reword to "should never contain" and say what actually holds it out (the shipped default is empty; `NO_PROXY=key-proxy` keeps provider calls off this route anyway).
- **Finding: P3** — the allow path (`establish` + tunnel through `handle`) has **no automated coverage**: `tests/container.rs`'s echo test drives `copy_bidirectional` directly (`egress.rs:791-796` says so), and every local upstream is loopback, which the address rule refuses. So the exact bug the doc says it fixed (`egress.rs:600-608`: a `Content-Length` on the `200` reads as a TLS record) would pass the whole suite. Smallest fix: a `#[cfg(test)]` resolve/connect seam so `handle` can be driven against a listener on a non-refused address (a fake `Target` + injected upstream).
- **Note (not a finding)** — attribution is a claim, not a proof: any container on any attached session network can send any session id, and the log cannot tell. ADR-0045 and the glossary say "attribution, not authentication", so this is recorded, not missed.
- **Spec verdict: OK with notes** — all seven acceptance bullets are implemented; the two reconciled deviations (`http://<id>@egress-proxy:3128`, `agent_image` + binary mount instead of `holosmith-proxy`) are exactly ADR-0045's decisions 1 and 5; the P2s are one logging gap and one ADR hand-over, not missing behaviour.

## Resolution

Every finding triaged. The P1 was real and it is the one this story was warned about in ADR-0044's own words:
the second container that starts at boot made the same unbounded `docker run` the probe already had a bound
for. The two spec P2s were real too — the byte counts vanished in exactly the case an operator reads them, and
ADR-0044 handed this story a decision that ADR-0045 did not answer.

| Finding | Verdict | What changed |
| --- | --- | --- |
| **P1** (Standards) — the proxy start is an unbounded `docker run` on the pre-bind startup path | **Fixed** | `Docker::bounded` is the one primitive (spawn, poll `try_wait`, kill on the deadline, answer `Ok(None)`), and `attempt` now uses it too. `run_detached(arguments, bound)` and `remove_container_bounded(name, bound)` are the startup spellings, bounded by `container::PROXY_START_TIMEOUT` (90 s: a first run may have to pull). `serve` logs a `warn` naming the bound on `Ok(None)` and continues — the listener must bind whatever the daemon does. |
| **P2** (Standards) — `apply_proxy` mutates a network endpoint outside the per-session start lock | **Fixed** | `provision_network` takes `self.start_lock(&session.id)`, as `provision_container` does, with the race that makes it necessary in the comment (a delete landing between the join and its leave-then-`rm`). |
| **P2** (Standards) — the daemon-gated test hijacks the machine-wide `hs_egress` | **Fixed** | The stand-in is `hs_egress_test`, and the test **skips** when `docker.running(PROXY_NAME)`: a test must not replace a live machine's proxy. That also gives `Docker::running`, which had no caller, the caller it was written for. |
| **P2** (Standards) — the test asserts the helper, not the backend's leave-then-removal | **Fixed** | After the alias assertions the test drives `SessionBackend::undo(&session, Step::Network)` and asserts the network is gone, so deleting the leave from `DockerBackend::remove_network` fails it. |
| **P2** (Spec) — bytes are lost when a tunnel fails, and a 400 leaves no record | **Fixed** | `Record::tunnel` is the tunnel (extracted from `handle`), and the copy is two counted loops over a split socket (`pump`, `pump_both`) that bump an `AtomicU64` **as bytes move**, because a `copy` that fails answers no count. A tunnel that cannot connect answers `unreachable` and one whose `200` cannot be written answers `unanswered`, both recorded; the two 400 paths record `not-http`. |
| **P2** (Spec) — ADR-0045 does not discharge ADR-0044's hand-over about host-bound services | **Fixed** | A "What is left" bullet: the proxy refuses to *tunnel* to such an address, a container that speaks to its own gateway never asks, item 4's guards are that path's defence, and closing it is HS-046's decision. Also added: the bounded start and the counted bytes as the two details a later story would undo. |
| **P3** — `address_problem` misses 6to4, NAT64, IPv4-compatible, site-local and 0.0.0.0/8 | **Fixed** | `embedded_v4` extracts the v4 destination from 6to4 (`2002::/16`), NAT64 (`64:ff9b::/96`) and IPv4-compatible addresses and recurses, so `64:ff9b::7f00:1` is refused as loopback; `fec0::/10` and the rest of `0.0.0.0/8` are named. Three table rows and two "outside" cases added. |
| **P3** — the allow path has no automated coverage (the `200`-with-no-body bug would pass) | **Fixed** | `Record::tunnel` is `pub(crate)` and the new test drives it against a loopback echo listener — below the policy, which is what makes it possible — and asserts the answer is exactly `HTTP/1.1 200 Connection Established\r\n\r\n` (no `Content-Length`, no body) and that 12 bytes moved each way. A second test asserts a 502 and a zero-byte record when nothing answers. |
| **P3** — `Rules::allow` has no doc comment | **Fixed** | It has one, and it says what reads it (the startup line's `allow=<n>` and a listener's print). |
| **P3** — the serve loop's doc says "until the listener fails", but it never returns | **Fixed** | The doc says it serves forever and that the signals are the caller's; a failed `accept` now pauses **escalating** (`ACCEPT_BACKOFF`, 5 s ceiling) and resets on a success, so a broken listener cannot fill the log at 600 lines a minute. |
| **P3** — `Rules::new` claims the config pass "validated `Crates.IO`" | **Fixed** | Reworded: the config pass *refuses* an uppercase entry; the flag is normalised instead of refused, because a container has no file to correct. |
| **P3** — `container.rs` names a `docker::connect` that does not exist, and "the one field (`ContainerSettings`)" | **Fixed** | `Docker::join_network`, and the sentence now names `EgressProxy::of` as the one thing that decides the mount. |
| **P3** — `remove_network`'s leave arm discards the `bool` and its message describes an unreachable path | **Fixed** | A three-way match: `true` (detached), `false` (nothing was attached — the ordinary answer), `Err` (the task did not finish), each with its own line. |
| **P3** — `docs/build.md`'s insertion broke a paragraph into three short lines | **Fixed** | Rejoined; the sentence reads "… would need the internet (ADR-0045). A case that must assert one code keeps…". |
| **P3** — GLOSSARY's Allow-list says it "never contains a provider host", which nothing checks | **Fixed** | "**should** never", plus what actually holds the two apart: an empty shipped list, `NO_PROXY=key-proxy`, and a review of any `[egress] allow` change as a review of where a session may send data. |
| **Note** — attribution is a claim, not a proof (any container on a session network can send any session id) | **Dismissed** | ADR-0045 and the glossary both say "attribution, not authentication", and the note agrees they do. A proxy cannot authenticate a caller it was built not to trust; what the network and the key proxy enforce is elsewhere. |
