# Review — PER-77 / HS-045 (`doctor --quick`, `doctor --full`)

Diff reviewed: `/tmp/holosmith/reviews/PER-77-diff.txt` against `0443d36` (3126 lines, workspace clean at launch; all story changes committed, so `watchdog_diff` shows only the operator's `log.txt`/`orchestrate.sh`).

## Spec

- **P2** `crates/holosmith/src/commands/doctor.rs:37-42` — `doctor` never creates the data root that `serve` creates before it preflights (`commands/serve.rs:58-64`), so on a machine that has never served, `disk` runs `df` on a missing directory and answers `fail` (`preflight.rs:510-531`), `doctor --quick` exits 1 on a machine `serve` would start, and item 10 step 1 (`server deploy` runs it before step 2 creates the directory) can never pass on a fresh host — the exact "the two commands cannot disagree about a machine" claim ADR-0028/ADR-0054 rest on. Smallest fix: report a missing `data_root` the way `database` reports a missing file (pass/unknown naming that `serve` creates it) — a `create_dir_all` here would just fail differently, since the service user cannot write `/var/lib`.
- **P2** `crates/holosmith/src/doctor.rs:214-217` (+ `:719`) — on a `hub` the Docker line is never pushed (`:192`), so `docker_ok` stays false and `--full`'s three container findings say *"…and the docker check above failed"* when the report contains no docker line at all; item 10 §6's `hub deploy` runs step 7 (`doctor --full`) on a hub, and a daemonless hub is the normal hub. Smallest fix: pass the reason into `not_measured` — a hub's sentence should say a hub asks no Docker question (item 10 §6), not that an absent line failed.
- **P2** `scripts/verify.sh:3053-3054` — the new "exactly one failure" assertion in `case_schema_newer` counts every `^word: fail: ` line, so a hub-class host whose tailscaled answers `NeedsLogin` (a legitimate `fail`, `doctor.rs:280-291`) fails this case under the schema case's name — the build.md rule "a case … asserts another guard's code under its own name". Smallest fix: count only `^database: fail: ` (the check this case owns).
- **P3** `crates/holosmith/src/doctor.rs:228-249` — `systemd` can never fail (pass or unknown only), so the acceptance's "Linux with systemd" is asserted nowhere; ADR-0054 argues this (HS-049 owns the refusal) and I agree, but the checkbox is only satisfied by a check with no failing arm — sign-off item, no code change.
- **P3** `crates/holosmith/src/doctor.rs:448-456` — the V2 checkbox's second half ("if the git version lacks it, the trial-merge fallback is implemented") is not implemented. The ADR records the decision, `RESUME.md` §1.6.5 offered it, and the reasoning holds because `MIN_GIT` *is* the release `--write-tree` arrived in, so a git that lacks it already fails on `git` and never reaches the trial. It is still a deviation from the contract the Linear body states; the deviation needs recording against the checkbox, not code.
- **P3** `docs/adr/0054-…md:3` — the ADR attributes the five-line acceptance quote to "the CLI's `holosmith doctor [--quick or --full]` row", but that row (`HolosmithSpec.md:349`) is only "Preflight checks and self-tests"; the quote is HS-045's slice / the issue body. One-word fix: name the story slice.
- **P3** `docs/adr/0054-…md` ("Ports are two moments") — the ADR justifies reading the held *preview* port against the control port's health answer with "`serve` binds both or neither", but a preview bind failure is one `warn` and the boot continues (`commands/serve.rs:214-226`, ADR-0051). No outcome is wrong today (an unbound preview port reads `is free`), but the stated reason is false; say "a free preview port is a pass anyway".

## Standards

- **P2** `crates/holosmith/src/doctor.rs:332` — the port check binds with `std::net::TcpListener`, which does not set `SO_REUSEADDR`, while `serve` binds with `tokio::net::TcpListener` (mio sets it), so a control port left in `TIME_WAIT` by the server that just stopped reads as `in use` and `doctor --quick` refuses the restart `serve` would happily bind — the `ExecStartPre` moment the story exists for. Smallest fix: in the `AddrInUse` arm, treat "nothing accepts a connect within `PROBE_TIMEOUT`" as free (with a sentence saying nothing is listening), so "in use" means a live listener. Needs the runtime check listed below.
- **P3** `crates/holosmith/src/preflight.rs:284` and `crates/holosmith/src/doctor.rs:169` — `preflight::report` and `Report::failures` are public API with no production caller (only tests use `failures`; nothing calls `report`), which is the non-goal the plan set for "a report with no consumer". Delete, or use `report()` from `check()` so the second spelling cannot diverge.
- **P3** Untested failing arms, so a behaviour change in them goes unremarked: `merge`'s `Err` (trial could not run, `doctor.rs:481`), `database`'s `Older` and `Err` (`:404-441`), `port`'s non-`AddrInUse` `Err` (`:352`), `tailscale`'s not-runnable arm (`:259`). One or two shim cases would cover all four.
- **P3** `scripts/verify.sh:4805` — the gate's `tailscale` assertion accepts `pass`, `unknown` *and* `fail`, so it cannot fail on any machine whose CLI answers; and `case_doctor_full` declares an unused `local line` (`:4883`). The first is the one gate assertion in this story that is close to vacuous.
- **P3** Doc/code mismatches: `docs/build.md:302-305` says `case_doctor_quick` asserts "the two honest `unknown` lines" where the case accepts `pass` too (`verify.sh:4797-4807`); `docs/build.md:340-345` still says `case_schema_newer` "takes a place at the end of the array" while `case_doctor_full` now follows it and the new paragraph says *it* is last; `docs/notes.md` (new section, last bullet) claims a `--full` run against a non-serving machine "reports both as failures", but the proxies are started by every `serve` and never stopped, so a stopped-but-previously-serving machine reads both `proxy: pass`.
- **P3** `crates/holosmith/src/doctor.rs:31-33` — the crate now has two `Outcome`s with different shapes (`preflight::Outcome` and `selftest::Outcome`) and two `Report`s; `doctor.rs` imports one `Outcome` and qualifies the other. The GLOSSARY entry for `Outcome` names only preflight's, and the new **Doctor** entry names no machine names at all (`Depth`, `Tools`, `Machine`, `Report`, `recorded_without_migrating`) while its sibling **Preflight** entry lists them. Worth one GLOSSARY sentence if nothing else.
- **P3** `crates/holosmith/tests/doctor.rs:459-461` — the comment says "a merge check that ran would pass" with the 2.37 shim; with that shim the conflict pair answers 0 and names no path, so a trial that ran would report `fail`. The assertion still catches the bug; only the stated reason is inverted.
- **P3** `RESUME.md:976` (`docs/stories/**` is not edited) vs the edit to `docs/stories/README.md` — the index line per ADR is what §7 asks for in the same paragraph and the ADR-0053 story did the same, so this is a rule conflict rather than a breach; noting it because §7 was on my list.

## Verdict

**OK with notes.** No P1: the projection refactor is real, the preflight's sentences are unchanged, the read-only open keeps ADR-0047's promise, `--full` passes on a genuinely healthy serving machine, and V2 is measured on a real repository. Three P2s to settle before ship: `doctor`'s missing-data-root disagreement with `serve`, the hub's "docker check above failed" line, and `case_schema_newer`'s cross-check failure count — plus the `SO_REUSEADDR`/`TIME_WAIT` restart risk, which needs the runtime check in item 3 before it can be graded.
