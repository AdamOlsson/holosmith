## Findings

**1. P2 — ADR-0066 D13's claim that "a name git would refuse is the body's shape: `422 bad_body`" is false for names `is_ref_name` accepts.**
`docs/adr/0066-the-publish-is-the-host-s-own-push.md:188-194` and the same claim at `crates/holosmith/src/publish.rs:236-240` (`parse_body`'s comment) and `crates/holosmith/tests/publish.rs` (`an_empty_or_impossible_destination_is_the_body_s_shape`'s comment) rest on `config::is_ref_name` (`crates/holosmith/src/config/mod.rs:900-913`) being git's refname alphabet. It is not: it checks empty/`@`/leading `-`/trailing `/`/trailing `.`/`..`/`@{`/whitespace/control/`~^:?*[\`, and never checks git's two other documented rules — a component beginning with `.` and the `.lock` suffix. So `branch: "a.lock"`, `".hidden"` and `"a/.b"` all pass the alphabet, are not protected and are not a target, and reach `git push` as `refs/heads/a.lock` etc. The answer is therefore *not* `422 bad_body`; it is whatever git says (most likely `409 push_rejected` with the sentence "fetch the remote's branch, integrate it and publish again", since a local `receive-pack` refuses a funny refname as `[remote rejected]`, or a `500 internal` if git refuses the refspec locally) — and that sentence names the wrong next step. Smallest fix: narrow D13's sentence to "a name the alphabet refuses is `bad_body`" (one sentence in the ADR plus the two comment copies), or add `!name.ends_with(".lock")` and "no component starts with `.`" to `is_ref_name` — one predicate, both callers, but it also tightens `merge.targets` config validation.

**2. P2 — ADR-0066 D14's order table puts "`branch` is a ref name" at step 5; the code decides it at step 1.**
`docs/adr/0066-the-publish-is-the-host-s-own-push.md:196-211` (rows 1–5) against `crates/holosmith/src/http/publish.rs:215-240` (`parse_body` validates `branch`'s alphabet before `respond` reaches the switch at `:135`, the `confirm` check at `:141` and `listed` at `:148`). Two observable divergences: with `[publish] remotes = []`, `{"remote":"origin","branch":"a..b","confirm":true}` answers `422 bad_body` where D14's row 2 says `403 publish_disabled`; with `{"remote":"upstream","branch":"a..b","confirm":true}` it answers `bad_body` where row 4 says `bad_remote`. The route's own module doc (`http/publish.rs:9-14`) and `parse_body`'s doc agree with the code, so the ADR table is the outlier. Smallest fix: fold row 5 into row 1 in D14 ("the body — `bad_body` / `unknown_field` / `branch`'s alphabet, shape first, then the key set") and renumber 6–12.

**3. P2 — the fourth `no_worktree` arm is untested, and the test says so without saying it is a gap.**
`crates/holosmith/src/http/publish.rs:110` (`NO_BRANCH`) and `:282` (`ChangesError::NoBranch => ApiError::no_worktree(NO_BRANCH)`) are reachable (delete `refs/heads/agent/<id>` with the worktree directory and registration intact) but nothing exercises them: `crates/holosmith/tests/publish.rs:625-627` covers three of the four by design. `docs/notes.md:2070-2072` records the merge's rule that such a line "needs a test of its own rather than a comment". Smallest fix: one more arm in `the_state_refusals_are_this_route_s_sentences` — `git update-ref -d refs/heads/agent/<id>` in the fixture's repository, then assert `409 no_worktree` and `"the session's branch is gone"`.

**4. S2 — `case_publish`'s two loop variables are not `local`.**
`scripts/verify.sh:6196` declares every case variable in one `local`, and the case's own next comment (`:6197-6199`) invokes the `local` rule; but `refusals` (`:6325`) and `arm` (`:6321`, the `for` variable) are assigned as shell globals. Nothing else in `verify.sh` reads either name today (checked), so this is latent, not a break — but it is exactly what the `local` line exists to prevent, and `case_publish` is the one case in the file that leaks. Smallest fix: add `refusals arm` to `local name=case_publish … refs_before`.

**5. S2 — ADR-0066 D8's "the command inherits the server's environment" has no test that can fail.**
`crates/holosmith/src/publish.rs:426-445` (`the_push_cannot_prompt_for_a_credential_and_injects_none`) pins `command.get_envs()`, which reports only *explicitly set* variables. Adding `.env_clear()` to `push_command` (`:319-327`) would leave that test green while destroying the acceptance bullet "pushes using the host's own git credentials" (no `HOME`, no `SSH_AUTH_SOCK`, no `GIT_CONFIG_*`) — and the integration pushes would still pass, because they push to a local path that needs no credential. This is the repo's own "a test that cannot fail" class (`docs/notes.md:528-531`, `:799-802`). Smallest fix: one behavioural discriminator — set `GIT_CONFIG_COUNT=1`, `GIT_CONFIG_KEY_0=remote.origin.pushurl`, `GIT_CONFIG_VALUE_0=<a second bare repo>` in the test process before `fixture.run(...)` and assert the ref landed in *that* repository; only an inherited environment can supply it (`-c` sets no pushurl, so the pin is untouched).

**6. S2 — the two new glossary entries are hard-wrapped where every other entry is one line.**
`GLOSSARY.md:576-589`: `**Publish**` and `**Protected name**` are broken over eight and five lines at ~105 columns, while every other entry in the file — including the `touches_ci` entry this diff edits at `:592-594` — is a single long line followed by its `_Avoid_:` line. Purely cosmetic, but it is a diff a reader sees. Smallest fix: join the lines to the file's one-line-per-entry shape.

## Verified by reading

- **The route's shape.** `POST /api/sessions/{id}/publish` is registered through `Routes::post` (`crates/holosmith/src/http/app.rs:609-621`), so `RouteKind::Mutating` is unexpressible otherwise and ADR-0010's three headers apply; `tests/publish.rs:721-737` reads the kind back from `App::manifest()`, and `tests/guards.rs:785-805` re-derives every route's kind (no exact-count manifest test exists to break).
- **The order, as code.** body → `publish.remotes` empty (`403`, before the row, `http/publish.rs:135`) → `confirm` (`:141`) → `listed` (`:148`) → `protected` (`:152`) → target (`:155-163`) → the row (`:165-177`) → `base_commit` (`:181`) → `spawn_blocking` (`:186`). Steps 1–7 read no row; the row's lock is taken and dropped without an `.await` (`:165-172`), matching `http/merge.rs:154-160`.
- **The push is a measurement, not a hope.** `push_arguments` (`publish.rs:302-313`) is `-c core.hooksPath=/dev/null push --porcelain --no-follow-tags <remote> <refspec>` with no `--force`/`-f`/`--all`/`--tags` and no `+` in the refspec; `push_command` (`:319-327`) adds exactly `GIT_TERMINAL_PROMPT=0`; `rejected_reason` (`:363-388`) reads only the porcelain `!` flag from stdout and never git's prose, and a non-zero exit with no `!` line becomes `ChangesError::Git` → `internal` rather than an invented refusal.
- **The answer cannot lie about `commit`.** `changes::basis` (`crates/holosmith/src/changes.rs:262-289`) returns `worktree.branch_head()` — `rev-parse --verify --quiet refs/heads/agent/<id>` (`worktree.rs:298-308`) — which is the same ref the refspec pushes from, and it is read before the push (`publish.rs:284`). Nothing in the route ever reports a value from git's push output.
- **No refusal pushes, and no push refuses after landing.** Every refusal is answered before `push_output` (`publish.rs:265-297`); the only post-push refusal is `Rejected`, which is the remote's own refusal of the one ref in the refspec, so "nothing was pushed" is true on all six arms. `every_refusal_says_that_nothing_was_pushed` (`http/publish.rs`) pins the phrase on all six constants.
- **The two-arm predicate is right.** `publish::protected` (`publish.rs:105-117`) indexes `name.as_bytes()[prefix.len()]` only behind `name.len() > prefix.len() + 1`, so `release/`, `release`, `releaser/x`, `release-notes` and `mainline` are all correctly unprotected; the unit test asserts both directions.
- **The credential assertion is non-vacuous and about the right container.** `tests/publish.rs:742-855` asserts the session container's mount vector is **five** mounts (`container.rs:231-249` emits exactly 5 × `-v`), that no mount names `.ssh`/`.gitconfig`/`.git-credentials`/`.netrc`/`.config/git`/`keys.toml`/`vapid.toml`/`/secrets`, that `.git/config` is `:ro`, that the `--env` set is non-empty and carries no `GIT_*`/`SSH_*`/`ASKPASS`/`CREDENTIAL` name (the eight real names are `HS_SESSION_ID`, `HS_PREVIEW_PORT`, `PI_CODING_AGENT_DIR`, the four `agent::ENVIRONMENT` entries and `HTTPS_PROXY`), and that the seed is exactly `settings.json` with exactly `defaultModel`/`defaultThinkingLevel` (`templates/pi-home/settings.json`). The positive half is the other tests' pushes into a bare repository under a `TempDir`.
- **The `pre-push` test is distinct and double-red.** The needle is a marker *file* under the `TempDir`, and the hook also `exit 1`s, so a hook that ran fails both `!marker.exists()` and the subsequent `.expect("the push lands")`.
- **The gate case is sound and self-contained.** `scripts/verify.sh:6195-6401`: own `projects-publish`/`data-publish`/`config-publish.toml`/`docker-publish.sock`/`publish-remote.git`, `python3` guard **above** `stop_serve` (the `case_worktree` rule), `idle_stop_min = 0` (the own-config pattern), one live session against `max_live_sessions = 1`, `[merge] targets = ["trunk"]` so `target_not_pushable` is reachable, four `422` arms each asserting status + code + sentence with the remote's `for-each-ref` unchanged, a rewound branch as `409 push_rejected` with the remote unmoved, and a **second boot** with `remotes = []` for `403` on the row and on an unknown id. `check`/`expect_status`/`expect_code` are called with the right arity (`verify.sh:173-195`), and no `publish` label collides with `case_merge`/`case_merge_guards`.
- **Docs truth.** `docs/build.md:264-280`'s case paragraph matches the case arm for arm; `docs/notes.md`'s new "Landmines: the publish" is the file's last section and every claim in it is true of the code (`remote get-url` exit 2 → `publish.rs:346-357`; the `!`-flag classification; the two pins); `GLOSSARY.md`'s `touches_ci` no longer says Publish reads it; `docs/stories/README.md:117` says "Sixty-six" and `docs/adr/` holds exactly 66 files with 66 index bullets, and the new link resolves.
