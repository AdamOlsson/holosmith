## Spec

**P1 · `scripts/verify.sh:11724-11725` (+ `:11752`, `:11796`, `:11805`) — `case_releases` is not daemon-free, contrary to its own header and to ADR-0084.**
The case's config sets no `docker_host`, so its five `doctor --quick` runs ask `unix:///var/run/docker.sock` (`preflight.rs:54`). `doctor::run` pushes the Docker check for every non-hub role (`doctor.rs:222-231`) and a socket that does not answer is a **fail** (`preflight.rs:327-336`) — so on the hub-class machine `docs/build.md:920-924` says the gate supports ("a machine without a daemon gets no binds and **every Docker check skips**") the three arms that assert `exit 0` go red with a message about `release:` lines that have nothing to do with releases. Meanwhile `scripts/verify.sh:11684` says "No daemon, no database, no `python3`" and `ADR-0084:148` says "(new; no daemon, no `python3`, no `SKIP` at all)". Every other daemon-free case in this file avoids exactly this with a `_ping` socket (`fake_docker_ping`, `verify.sh:8163-8204`; `case_doctor_quick:10224-10227` states the reason: "deterministic on every machine — including one with a real daemon"). It is green here only because this machine has a daemon.
*Smallest fix:* point the case's config at its own socket — add `docker_host = "unix://%s/docker.sock"` to the printf at `:11724` and start `fake_docker_ping "$WORK/docker-releases.sock"` (killed at the end) behind the `command -v python3` guard the file already uses for such cases — and let the header/ADR say "one `_ping` socket" instead of "no daemon". If the python3 dependency is unacceptable, the honest alternative is to stop asserting exit 0/1 there and assert only the `release:` words — but the exit code *is* the acceptance's "a broken `current` refuses a boot", so the shim is the better half.

**P2 · `crates/holosmith/src/doctor.rs:602-609` — the hand fix is not actionable in one of the four arms it is printed for.**
When `current` is a **directory**, the state sentence says so (`:582-587`), but `fix` is still `Point it at a release that exists — \`ln -sfn releases/{newest} {current}\``, and `ln -sfn` refuses a directory destination ("cannot overwrite directory"). The repo's standard here is the acceptance's "one actionable line per failure", which this line otherwise keeps.
*Smallest fix:* make `fix` depend on the state — `rm -rf {current} && ln -sfn releases/{newest} {current}` for the not-a-symlink arm, the plain `ln -sfn` for the rest.

**P3 · `docs/adr/0084-…:148-150` and `scripts/verify.sh:11400-11417` — two small measurement claims that the code does not quite keep.**
D6 says "four `doctor --quick` runs" and lists four; the case makes five (the `unknown` arm, `verify.sh:11803-11808`). And "the prune is the last line because it is the last thing that happens" (ADR-0084:47-50, `docs/build.md:1451-1452`) is asserted only by the printed line's prefix — nothing checks it is the final line, though the case's order loop stops at `live:` (`verify.sh:11350`).
*Smallest fix:* "five" in D6 (or add the `unknown` arm to its list), and one `check "$name/prune/last" … "$(tail -1 …run.out)"` in `case_upgrade`.

**Checked and found sound (Spec)**

- Bullet 4 (prune to a count, never live or rollback target): the reservation is `Release::protected` = `current`'s tag + `older_than` it (`release.rs:205-213`), counted *inside* `keep` (`:230-247`); the discriminating fixture — `current` on the **oldest** release — exists and would fail under a "newest N" rule (`release.rs:735-755`); the function floors itself at the protected set (`:757-770`), and the `case_upgrade`/`tests/upgrade.rs` arms would each fail if the prune were deleted (they assert a directory is gone) — I noted that "newest N" would *not* be caught by `tests/upgrade.rs` or the gate alone, only by the `src/release.rs` fixture, so that fixture is load-bearing.

- The deploy exemption's argument is true of the code: `service_line` renders the unit for `current_exe()` exactly when `Release::live(target)` is `None` (`deploy.rs:1850-1853`), which is the broken-link case, and step 7 then finds the release line passing, so the exemption does not merely move the failure one step later.
- No second spelling of "what is live": `doctor` asks `Release::live` and `release::unit_executable` only; nothing new reads `current` directly.
- No scope creep outside the story's bounds: no new verb, no `web/` change, no `docs/stories/**` edit beyond the ADR index, no database restore; `doctor --root` is a flag, and ADR-0084 D4 plus `docs/notes.md` record it as a decision.
