### Answers to the seven hunts (evidence, not verdicts)

1. **Can the cap be exceeded? No counter-example.** `head.len() == total.min(DIFF_CAP)` by construction (`changes.rs:493-497`), and `truncated` is `total > head.len()` (`changes.rs:537`), so truncated ⟹ `head.len() == DIFF_CAP`. Budget arm: `kept ≤ DIFF_CAP − marker.len() − 2` (`:548`), then only shrinks (`:550` line floor, `:555-560` UTF-8 floor); body = `kept` + at most one `\n` + marker + `\n` ≤ `DIFF_CAP` exactly. Untruncated arm returns `head` whose length is `total ≤ DIFF_CAP`. `saturating_sub` cannot bite (marker is 72–100 B). Invariant holds on every path, including empty output and the non-UTF-8 floor.
2. **Path reaching git without membership? No.** `respond_diff` (`http/changes.rs:112-133`) → `path_of` (`:177`) → `decode` (`:197`) → `diff` (`changes.rs:399`), where `files()` runs at `:403` and the exact-equality test at `:404` returns before `patch_arguments` at `:410`. `..`, an absolute path and `sub/../a.txt` are all compared, never joined (test at `tests/changes.rs:1088-1110`). One residual: the *string* is exact but the *pathspec* git receives is not literal (see Spec P3‑1).
3. **141/SIGPIPE story: right for `verify.sh`, and `run_patch` has no SIGPIPE/verdict bug.** `sed …q` under `pipefail` is the correct diagnosis (`verify.sh:198-209`, `docs/notes.md:1081`), and `expect_status`/`expect_code` are safe because they do not quit early. In `run_patch` the read end is never closed before `wait`, the ceiling path kills then waits (`changes.rs:486-490`), and the status is only a verdict when `complete` (`:513`) — so a deliberately cut diff cannot become a 500, and no zombie on any reachable path. Two residuals (Standards P3‑2, P3‑3).
4. **Refusals byte for byte? Yes.** Both handlers route `ChangesError` through the same `refusal()` (`http/changes.rs:247-252`, called at `:91` and `:157`), and both use the same `NO_WORKTREE` constant (`:38`, `:82`, `:126`). Nothing is re-spelled.
5. **Over-claims: three found** (Standards P2‑1, P3‑1, P3‑2) — see below.
6. **No new test is unable to fail**; one is fragile (Spec P3‑2), and one recorded decision is unmeasured (Spec P3‑3).
7. **`case_changes_diff` owns its state** (own `mktemp -d` `$WORK` at `verify.sh:88`, own projects root `:5258`, own data root, own `_ping` socket, re-makes the worktree itself) and **cannot skip on its own subject** — a missing route fails loudly. The one weak guard is `seq` (Standards P3‑4).

## Standards axis

- **Correct:** the extraction of `basis()` (`changes.rs:258-284`) is a real de-duplication, not a rename: both readers share the four ordered refusals and the tip, and `Changes::read` lost exactly that block. `git_error`/`git_error_from` (`worktree.rs:592-622`) keeps one spelling of "what git said" for a caller with no `Output`. `--` before the path, `--no-color` kept out of `DIFF_FLAGS`, and the "one list of answer-changing flags" rationale are all documented where a reader will look. `case_changes_diff` follows the house rules it must (two `local`s for the `set -u` landmine `:5257-5261`, guards before `stop_serve`, `cmp`/`wc`/`tail` only, byte comparison against git's own `git diff` rather than against the artifact's own arithmetic).
- **P1: No issues found.**
- **P2-1 — `scripts/verify.sh:5329`: the case's comment states the wrong constant.** It says "`changes::COUNT_MAX` is 2 MiB of diff"; `COUNT_MAX = 8 * DIFF_CAP` is 8 MiB (`changes.rs:123`). A reader sizing a future fixture from this line would believe a ~3 MiB patch gets "longer than". Smallest fix: `8 MiB` (and, while there, the `60000`-line file is ~409 KB, not "~1 MB").
- **P2-2 — `docs/notes.md:1081-1085` is now a false claim about code the same diff changed.** The HS-033 landmine still says `expect_header`/`expect_no_cors` "pipe their argument through `sed '/^\r$/q'`" and that "both helpers' call sites read the *header block* off the saved file now (`sed '/^\r$/q' "$file"`); a new case with a large answer must do the same" — but the diff replaced that cut with bash's own `${response%%$'\r\n\r\n'*}` (`verify.sh:203-206`, `:355-358`), and `case_changes_diff` deliberately passes `"$(answer …)"` (the whole 256 KB response) to `expect_header` (`verify.sh:5354`), which the note forbids. The notes' own rule is to delete a claim that stopped being true rather than add a caveat beside it (`notes.md:459-460`). Smallest fix: rewrite that one bullet to name the new mechanism and delete the call-site instruction.
- **P3-1 — `docs/adr/0062…md:121`: "Memory is the cap plus a chunk" over-claims.** stdout is bounded, but stderr is `read_to_end`ed into an unbounded `Vec` (`changes.rs:474-480`), so memory is `DIFF_CAP + CHUNK + whatever git says on stderr`. Smallest fix: either qualify the sentence ("stdout's memory is the cap plus a chunk; stderr is bounded by what git prints") or cap the drain.
- **P3-2 — `changes.rs:580-587`: the "longer than N" marker is not strictly true at the boundary.** The ceiling is tested at the top of the loop (`:486`), so a diff of *exactly* `COUNT_MAX` bytes that git had already finished printing is reported as "the diff is longer than 8388608 bytes". Smallest fix: word it "at least N bytes", or only claim "longer than" when a further read still returned bytes.
- **P3-3 — `changes.rs:371-380`: new dead public API with an untrue doc.** `DiffError::sentence` has no caller in `src/` or `tests/`; its doc says it is "the sentence an operator reads in the log", but `diff_refusal` logs only the path via `tracing::debug!` (`http/changes.rs:163-167`) and `refusal` logs `%error` for the Git arm. The pre-existing `ChangesError::sentence` is likewise uncalled, so this adds a second copy of an unused shape. Smallest fix: delete `DiffError::sentence`, or use it in the `NotChanged` log line so the doc becomes true.
- **P3-4 — `scripts/verify.sh:5267-5270`: the `seq` guard can drop the whole case over a fixture.** Unlike every neighbouring guard (python3/docker are real dependencies of the measurement), `seq 1 60000` is replaceable by a shell loop, so the case skips its six assertions — cap, marker, binary, 404, 409 — for a reason unrelated to the feature. Smallest fix: drop the guard and generate the file with `while`/`printf`.

## Spec axis

- **Correct (all five acceptance bullets, measured not asserted):** `GET …/changes/diff?path=` returns a unified diff compared byte-for-byte with the test's own `git diff` (`tests/changes.rs:899-923`, gate `cmp -s` at `verify.sh:5343-5345`); the 256 KB cap with a marker naming git's own total, marker inside the cap (`changes.rs:535-573`, `tests/changes.rs:948-983`); `--no-ext-diff --no-textconv` pinned *and* measured against a repository-local `diff.external`/`textconv`/`color.ui` (`tests/changes.rs:998-1075`); binaries summarised by git's own line with no NUL on the wire (`tests/changes.rs:944-947`, `1179-1191`); `path` validated against `files[]` with `..%2Fetc%2Fpasswd`, `%2Fetc%2Fpasswd` and an unchanged path all `404 not_found` and no leak canary (`tests/changes.rs:1218-1246`, `verify.sh:5406-5420`). Item 12's governing sentence holds: host git in the project repository, `spawn_blocking`, no container, no write (D10 as recorded).
- **P1: No issues found.**
- **P2: No issues found.**
- **P3-1 — `changes.rs:423-436`: the member's name reaches git as a *pathspec*, not literally.** Membership is exact (`:404`) but `patch_arguments` passes the raw string after `--`, so a changed file whose name contains `*`, `?`, `[` or a leading `:` is glob/magic-interpreted by git (`?path=docs/a*.md` returns the union of every matching changed file; `:!x` inverts). Not a leak — the result stays inside this branch's own changes and the whole-branch answer is available anyway — but the answer is not "the diff of that path". Smallest fix: `git --literal-pathspecs diff …` (or prefix `:(literal)`).
- **P3-2 — `changes.rs:1116-1134`: the UTF-8-floor test is one byte of marker text away from testing nothing.** With today's marker length (72) the budget lands at 262070, i.e. the first byte of an `é` — so the `error_len() == None` arm is exercised. Change the marker's wording by one byte and the cut lands on a character boundary, `from_utf8` succeeds, and the test still passes with the floor deleted (it only asserts the body is valid UTF-8). Smallest fix: assert the cut was mid-character (e.g. `assert!(diff.body.len() < 262144 - marker_budget)`), or drive both parities with a 1- and a 2-byte prefix.
- **P3-3 — `docs/adr/0062…md:97` (D6): "an empty branch is a `200` with an empty body" is measured nowhere.** No module test, wire test or gate case asks for a branch with no commits, so the second half of D6 rests on code reading alone. Smallest fix: one module test on a fresh `Fixture` asserting `diff(&worktree, &base, None)` gives `total == 0`, `!truncated`, empty `body`.

**Merge verdict: OK with notes.** No P1 on either axis; the two P2s are comment/doc accuracy in `scripts/verify.sh` and `docs/notes.md` (both 1–3 line edits) and can land in the same commit. I ran no tests — nothing above needs one, except optionally the pathspec repro: `git diff --no-ext-diff --no-textconv --no-renames --no-color <base> <head> -- 'docs/a*.md'` in a repository whose branch changed both `docs/a*.md` and `docs/abc.md`.
