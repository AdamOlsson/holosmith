## Review — PER-110 / HS-078 (f2b3886..f71aec0)
**Verdict: BLOCK** — the pipeline, the two refusals and the resume rule are measured and honest, but one class of refusal (S1) contradicts three documents this change itself wrote, and two smaller claims are untrue (S2, S3). All three are one-sentence edits.
## Spec axis
**S1 — P1. Every refusal *after* the drain except one is silent about the machine being draining.** `promote.rs:347` says in the code's own words "from here on the machine is draining, **which every later sentence says**", then `promote.rs:348-360` returns `take_backup`, `previous_release`, `write_release`, `write_unit` and `switch` failures with `?`, verbatim — "already holds a different binary for `v0.1.0`", "`current` names releases/<tag>, and … is not there", "… could not be written (Permission denied)". Only `take_backup`'s *write* arm names the state (`promote.rs:532-537`); its two earlier arms (`promote.rs:516-524`, "there is no database at …", "could not be opened") do not. This contradicts the change's own record: `docs/build.md:1458-1459` ("every one of those leaves the machine as it found it and says so — except a refusal *after* the drain, which leaves the machine draining and says that the restart is what clears it"), `GLOSSARY.md:996-997`, and `cli.rs:88-89`. The build.md list at `:1457` names exactly the step-6 refusals ("a unit that is not there and a `current` that names something which is not a release") as covered. *Smallest fix:* one `.map_err(|said| format!("{said} — this machine is draining until it is restarted (`systemctl restart {}`)", deploy::UNIT_NAME))` around the step-6 block, and the same clause on `take_backup`'s two early returns.
**S2 — P2. The "already draining" refusal names a remedy that cannot work.** `promote.rs:323-330`: "… `holosmith drain --wait` will say again when it has finished". Nothing clears the flag but a new process — `Control::begin` is the only writer (`drain.rs:128-131`; there is no `clear`). So `drain --wait` answers `drained` (it joins and finishes) and the flag stays set: the operator's next `upgrade` is refused again by the same sentence. This is reachable from this command alone: any post-drain refusal of S1's group leaves exactly that state. *Fix:* name `systemctl restart holosmith.service` as the thing that clears a drain, and say that a drain this machine is already in (rather than somebody else's) is indistinguishable here.
**S3 — P2. `Options.window` is not the poll's window.** `serve_with` passes the constant, not the parameter: `promote.rs:715` (`WINDOW`) versus `742` ("no answer with {} in {}s" using `window`) and `783` (the rollback *does* pass `window`). `promote.rs:58-62` claims WINDOW is "a parameter everywhere below it", `:77-80` justifies `Options.window` as "a parameter for the reason … a test that had to wait the spec's twenty seconds … would be a test nobody runs", and ADR-0082 D11 repeats it. Consequence: `tests/upgrade.rs:41`'s `WINDOW = 60ms` ("short enough that a poll which gives up does so now") is ignored, and `a_candidate_that_never_answers_…` polls the full 20 s. *Fix:* pass `window` at `promote.rs:715`.
**Correct, and worth recording:**
- Both refusals the acceptance names are measured before anything is switched, and in the right place: the schema one reads **without migrating** (`promote.rs:486-511` → `db::recorded_without_migrating`, `db.rs:503`), and "already draining" is the server's own first line (`drain.rs:256`, `ALREADY:102`, compared at `promote.rs:162-172`) — which is genuinely the first line for a valid request (`drain.rs:686-699`). Stopping the read does not hurt the other drain: writes are non-fatal and the sequence runs on (`drain.rs:479-483`, `683-685`, `705-712`).
- The rollback limit is **real**, not a worry: `doctor::database()` runs at both depths (`doctor.rs:232`) and fails on `Verdict::Newer` (`:487-493`), so `ExecStartPre=doctor --quick` does block a schema-advancing rollback exactly as ADR-0082's header, `docs/build.md:1462-1466` and notes.md say — and the loudest rollback sentence names it.
- Bullet 3's resume is on the right seam: `reconcile.rs:115-127` selects `stopped` + `SERVER_RESTART`, `Recovery::trigger` (`:90-97`) chooses `Resume`, which the table admits from `Stopped` (`state.rs:251-254`); the reason is cleared because the transition applies with `None` (`reconcile.rs:365-368` → `state::apply` → `set_status(reason)`), and the settle reason is `None` too (`:390-393`). Neither pass, the sweeps nor `interrupted()` change meaning.
- Bullet 4 is one function with two callers (`images.rs:710-732`) and the tags are the **candidate's** (`:118-130`, `191-206`); `Kind::image_of` is the single spelling.
**S4 — P3. `case_upgrade`'s schema arm hardcodes the version.** `verify.sh:11124-11130` writes `range(1, 9)`. With `SCHEMA_VERSION = 7` (`schema.rs:17`) `verdict(8, 7) == Newer` (`:161`) so it refuses today — but the day schema 8 ships the arm produces no refusal and dies at `check "$name/schema/exit" 1`. *Fix:* one more than the artifact's own `version --json` `schema_version`.
**S5 — P3 (note, not a hole).** `tests/upgrade.rs:254` and its seven siblings skip when `dist/<triple>/holosmith` is absent, so on a first run `cargo test` — the gate's `test` phase, which runs before `build` (`verify.sh:13375-13387`) — measures none of bullet 1's order, and libtest swallows the `eprintln` of a passing test. It is `tests/images.rs:688-694`'s established convention, and `case_upgrade` measures the same order from the artifact, so the gate as a whole is honest; a would-be fixer should know the Rust half is vacuous on a clean tree.
## Standards axis
**T1 — P3. A duplicated, stale comment in `case_upgrade`.** `verify.sh:11057-11069` and `:11070-11082` are two copies of the same header, and the first describes a fixture that does not exist: "the same promotion of a candidate whose version and tag were rewritten". The case uses `HS_BREAK_FIRST`; notes.md's own landmine says the rewrite is impossible ("A static binary's strings are not in `.rodata` … not a fixture this repository can have"). *Fix:* delete the first copy.
**T2 — P3. Over-claim in the poll's doc.** `promote.rs:836-838` and `:849-851`: "a process younger than the restart is a process this command started". `uptime_s <= elapsed + 1` establishes only "started after this instant", which any starter satisfies — and since two builds of one `CARGO_PKG_VERSION` are indistinguishable there (always true here), uptime is the sole discriminator. ADR-0082's "What this does not measure" bounds it; the sentence should say "started after the restart".
**T3 — P3. `deploy`'s step-5 fallback is untested.** `deploy.rs:1789-1800` prefers `Release::live`; `tests/deploy.rs:2780` covers only a tree whose `current` resolves. Reading `release.rs:147-155`, a broken `current` (dangling, or a tag whose binary is gone) yields `None` → `current_exe`, so no unit that fails to start is written — but nothing asserts it.

## Resolution

| # | Finding | Answer |
| --- | --- | --- |
| S1 | P1 — refusals after the drain were silent about the machine draining | **Fixed.** `promote::draining(String)` is the one clause, applied to every refusal after a successful drain (`take_backup`, `previous_release`, `write_release`, `write_unit`, `switch`); `take_backup`'s own private copy of it was deleted, so the five call sites cannot drift. `tests/upgrade.rs::a_backup_that_cannot_be_written_leaves_the_previous_release_live` now asserts the clause, so a future refusal that drops it fails a test rather than a document. |
| S2 | P2 — the "already draining" sentence named a remedy that cannot work | **Fixed.** Both drain refusals now say a drain is cleared by **the restart it exists for** (`systemctl restart holosmith.service`) and not by finishing, which is what `Control::begin` being the only writer means. The reviewer is right that the old sentence was reachable from this command alone: any S1-group refusal left exactly the state it mis-described. |
| S3 | P2 — `Options.window` was not the first poll's window | **Fixed, and it was a real defect.** `serve_with` passed the `WINDOW` constant instead of `window`, so `tests/upgrade.rs`'s 60 ms window was ignored and the rollback test waited the spec's 20 s. Measured after the fix: `cargo test --test upgrade` went from 23.16 s to 4.38 s. |
| S4 | P3 — the gate's schema arm hardcoded 8 | **Fixed.** One more than the schema the artifact's own `version --json` reports (`schema + 1`), so the arm cannot stop being a refusal the day this build ships schema 8. |
| S5 | P3 — the Rust half of the order is vacuous on a clean tree | **Noted, not changed.** `tests/upgrade.rs` needs a static ELF that answers `version --json`, i.e. `dist/<triple>/holosmith`, which the gate's `test` phase may not have yet — the same convention `tests/images.rs`'s `ready()` established. The gate as a whole is honest because `case_upgrade` measures the same order from the artifact with real children; the skip's own note says so, and `docs/notes.md`'s *Tests* section already records the shape. |
| T1 | P3 — a duplicated, stale comment above `case_upgrade` | **Fixed.** The first of the two header blocks was the previous version of the case (it described a patched-artifact fixture this story measured to be impossible, `docs/notes.md`'s `movabs` landmine); deleted. |
| T2 | P3 — the poll's doc claimed "a process this command started" | **Fixed.** The doc and the inner comment now say what `uptime_s <= elapsed + 1` establishes — a process that **started after the restart** — and say explicitly that it does not say *which* binary. ADR-0082's "what this does not measure" carries the same limit. |
| T3 | P3 — `deploy`'s step-5 fallback was untested | **Fixed.** `tests/deploy.rs::a_release_tree_makes_the_unit_run_through_current` gained a third run after removing the live release's binary: step 5 is `changed`, the unit no longer names `current/holosmith`, and it falls back to the binary the deploy is (`ExecStart=<current_exe> serve`). |

Both "correct, and worth recording" sections were checked against the code and are unchanged; nothing in the review's *Could not verify without running* list is left unmeasured — the full gate (`scripts/verify.sh`) and the demo are what ran them, and §9 of `RESUME.md` quotes the numbers.
