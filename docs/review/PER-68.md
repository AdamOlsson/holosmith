# Code review — PER-68 / HS-036 (per-session network and the startup self-test), `60eaac3..HEAD`

## Standards

**Verdict: OK with notes** — no P0; two P1s (a missing ADR amendment note and a duplicated glossary entry) that should be fixed before release; the rest are prose/hygiene.

- **P1 — ADR-0028's "a check that cannot run is never a pass" was changed, and ADR-0028 carries no "Amended by" note.** `docs/adr/0028-the-docker-preflight.md:42-47` states the rule in bold ("`docker_host` on an `ssh://` host is a complaint, and so is a `df` or `git` that is missing or refused … This is the rule that keeps a preflight from being decoration"), and `GLOSSARY.md`'s **Preflight** entry repeats it ("A check that cannot run … is a complaint rather than a pass"). The new self-test deliberately makes "could not run" a `warn` and serves (`crates/holosmith/src/selftest.rs:14-20`, `crates/holosmith/src/commands/serve.rs:120-131`). ADR-0044 argues the distinction well but never mentions ADR-0028, and this repo requires the note (precedents: `docs/adr/0018…:22`, `0019…:67,71,80`, `0027…:24`, `0040…:74`, `0041…:69`; and PER-66's P1 was exactly an unamended ADR). Smallest fix: one line under ADR-0028's "A check that cannot run is never a pass" — "**Amended by ADR-0044:** the network self-test's `Unknown` is a `warn` and the boot continues; the three checks above still refuse."
- **P1 — the glossary grew a second `Session network` instead of updating the first.** `GLOSSARY.md:490-494` adds a new entry while `GLOSSARY.md:530-532` already defines the same term. They disagree on `_Avoid_` lists and on the machine name, and the older one now says "HS-036 adds the two proxies and the startup self-test that make 'only the key proxy answers' a fact" — which ADR-0044 §"What this story does not do" explicitly denies ("`HS-037` … and `HS-039` … this story only guarantees the network they attach to exists"). A glossary whose whole job is "one canonical name per concept" now has two, one of them false. Smallest fix: delete `GLOSSARY.md:490-494` and update the existing entry at `:530` (add the `--internal`/`create_internal_network` machine names, drop the proxies claim, keep one `_Avoid_` list).
- **P2 — a mangled log sentence.** `crates/holosmith/src/commands/serve.rs:117` — the egress `warn!` reads "…no route out through the                      proxies…" (a run of ~22 spaces from a botched reflow). This is text an operator reads on every Docker boot of a machine whose daemon cannot create networks.
- **P2 — "no gateway" contradicts ADR-0044 on a fact the ADR measured.** `crates/holosmith/src/selftest.rs:4` ("so there is no gateway and no route out") and `GLOSSARY.md:491` ("so it has no gateway") vs `docs/adr/0044-…:33` ("An `--internal` network still reports an IPAM gateway in `docker network inspect` (measured: `172.21.0.1`) — the address exists and nothing routes to it") and this same change's own comment at `crates/holosmith/tests/container.rs:294-297` ("the gateway field lies about reachability"). The ADR owns the truth; two new prose sites round it back to the wrong reading. Fix the two sentences, not the ADR.
- **P2 — startup can now block indefinitely on a subprocess, with no deadline.** `crates/holosmith/src/docker.rs:88-190` (`run`, `succeeds`, `inspect`, `attempt`) all call `Command::output()` with no timeout, and `serve` now performs one `docker network create` plus one `docker run` *before* the banner (`serve.rs:110-127`). `preflight.rs:36-40` documents why that is a hazard ("a startup that waits for it is the failure this preflight exists to prevent", `PING_TIMEOUT` = 3 s); ADR-0044:80 offers only "about a second" and no bound. The in-container probe bounds itself (3 s per target), but `docker run` itself does not. Smallest fix: note the exposure in ADR-0044 and/or give `attempt` a deadline (a thread + `recv_timeout`, the shape `verify.sh`'s `start_serve` uses) — or at minimum record that a wedged daemon hangs the boot here.
- **P2 — `docs/build.md`'s image prerequisite is now incomplete.** `docs/build.md:385-389` says the test image "needs `sh` and `git`". The probe also needs `node` (`templates/selftest-probe.js`), and a missing node is `Unknown` (exit 127) — a `warn` at *every* boot rather than a failure, i.e. silently unmeasured. `docs/build.md` is a story deliverable whenever prerequisites change.
- **P3 — `preflight.rs:7` still says "Three checks, and only these three"** while `Check` now has four variants (`preflight.rs:57-63`). The variant's own doc explains that `check` never answers it, so the module doc could say "four variants, three of them answered here".
- **P3 — `docker.rs:140-142`** claims `gateway` answers `None` for "no IPAM config (an internal one, …)"; an internal network *does* report IPAM config (`ADR-0044:33`). Only ever called with `"bridge"`, so prose only.
- **P3 — `GLOSSARY.md:510-513`** three stray blank lines between the **Self-test** entry and **Key proxy**; **`docs/build.md:440`** has trailing whitespace and ends mid-sentence on a colon, so the paragraph was appended rather than reflowed (~100 cols, the rule in `RESUME.md:1146-1148`).
- **P3 — `Docker::attempt` returns `crate::selftest::Report`** (`docker.rs:145-170`) and takes `&[String]` while every sibling takes `&[&str]` (`docker.rs:88,99,121,180,196`). The generic CLI wrapper now depends on one feature module's type; a neutral return (or `Report::from`) in `selftest.rs` would keep `docker.rs` feature-free. Judgement call.
- **P3 — `verify.sh:1502-1546`** `case_network_selftest` cleans its scratch root at the start (`:1517`) but not at the end, unlike `case_docker_turn` (`:760,924`), so `target/verify-selftest-<pid>/{projects,data}` survives a green run.
- **P3 — `RESUME.md:1651`** (added by this diff) says "`case_docker_container`/`tests/container.rs` see the flags", but no `case_docker_container` exists: `scripts/verify.sh` only has `case_container_mounts` (`:359`). The stale name predates the diff (`RESUME.md:1245,1258`), but this hunk reproduces it.
- **P3 — `RESUME.md` is the *previous* session's refresh, landed inside this range.** At HEAD it says ``HEAD` is `60eaac3`` (`:46`), "39 Done" (`:49`), "**Not built yet:** the `egress` network and its startup self-test (HS-036)" (`:828`), "38 test binaries" (`:592`) and "now **forty-three**" ADRs (`:1153`) — all false once this story's code and `tests/selftest.rs` are in. The repo's supported-machine rule is stated for "no daemon" (`docs/build.md:385-387`), not "no internet", so this is an unstated new environmental requirement.

Compliant, checked explicitly: at least one `case_*` + one `serve_cases` line (`verify.sh:346,1502`) and it sits **last** in the array as a self-booting case requires (`docs/build.md:243-247`); the check runs before what it protects (before `Database::open` and before the listener, `serve.rs:87-127`); the machine-dependent check is tested through a seam (`selftest.rs`'s `Runner`/`Fake`, the `preflight::Tools` pattern); **no `info!`** and the eight-line banner pin is intact (`tests/serve_cli.rs:181-201` boots `--backend stub`); one `SKIP` line and a pass where there is no daemon/image (`tests/selftest.rs:25-35`, `verify.sh:1506-1516`); no `awk`, no `shellcheck`, no new dependency/config key/image; `docs/stories/phase-1b-docker-backend.md` untouched while `docs/stories/README.md:117` moves 43→44 with a resolving ADR-0044 bullet; no pi version literal in a second tracked file; ADR-0044 behaviour matches its own text for `Passed`/`Failed`/`Unknown`, the always-remove rule, and the egress `warn`; no baseline smell worth naming (the `Runner` trait is not speculative — three outcomes are driven through it).

- **P2 — the passing line asserts something that may not have been measured.** `serve.rs:134-137` logs "the network self-test passed: an internal network reaches **neither the internet nor the host**", but `Docker::targets()` (`selftest.rs:140-149`) returns **one** target when `gateway("bridge")` is `None` (rootless daemon, no bridge), and `Outcome::Passed` is a unit variant carrying no targets, so nothing on the pass path records that the host was never probed. - **P3 — the host is probed only through the default bridge's gateway, never through the internal network's own gateway.** `selftest.rs:140-149` targets `bridge`'s gateway + 2375; ADR-0044:33 in the same change measures that an `--internal` network *does* report an IPAM gateway (`172.21.0.1`) and asserts "nothing routes to it" without probing it.
