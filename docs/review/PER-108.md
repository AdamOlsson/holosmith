## Verbatim

### Standards

**P1 — the recipe's rust toolchain comes from `rust:latest`, not the pinned digest.**
`crates/holosmith/images/builder.Dockerfile:16` declares the second base with no stage name:

```
FROM rust:1.99.1-bookworm@sha256:e6f2cff3…
```

but `:20-21` copies from a name that only exists as an *image*:

```
COPY --from=rust /usr/local/rustup /usr/local/rustup
COPY --from=rust /usr/local/cargo /usr/local/cargo
```

Docker resolves `--from` against **stage names** first (`AS node` at `:15` is why `--from=node` works) and otherwise as
an image reference, so `rust` is `docker.io/library/rust:latest`: an extra, unpinned, ~1.4 GB pull, and
`rustc`/`cargo` come from whatever `latest` is today. The pinned `FROM` byte only supplies the stage's base distro.
This contradicts the file's own comment (`:18-19` "taken from the pinned rust image … the thing a pinned builder
exists to avoid") and ADR-0080 D2 ("two bases by manifest-list digest"). Nothing can see it:
`src/builder.rs:the_recipe_pins_both_bases_by_digest` reads only `FROM` lines, and `tests/build.rs` compares node
digests only. Smallest fix: add `AS rust` to `:16`. Supervisor, to confirm: build the image with `--progress=plain`
and look for `load metadata for docker.io/library/rust:latest`; if `rust:latest` ever leaves bookworm, the copied
`rustc` needs a newer glibc than the pinned base and the failure will look unrelated.

**P2 — `scripts/verify.sh:42-47`, the usage header is a broken sentence.** The HS-076 clause was inserted mid-sentence,
leaving `… and a Docker preflight that` (`:42-43`) immediately followed by `the release build of HS-076 in a case of
its own (…)` and then a second `and a Docker preflight that` (`:46`). `usage()` (`:57`) prints exactly these lines.
Fix: move the `case_build` clause before `, and a Docker preflight that` on `:41` and delete `:43`.

**P2 — `scripts/verify.sh:10900` dead locals.** `plain said status artifact_line digest_line` are declared and never
used; the case's real names are `log compiled built fake recipe`. Report-only.

**P2 — `docs/stories/README.md` lost its final newline** (`\ No newline at end of file` in the diff). Every edit to
that file re-appears as a two-line diff until it is restored. (The count `Eighty` and the ADR-0080 bullet are correct;
0001–0080 is 80.)

Smells, accepted: `Docker::build_bounded` (`src/docker.rs:440`) is now a Middle Man over `run_captured` — kept
deliberately so HS-048's call sites and their doc contract stay unchanged. `commands::build::execute` mixes ordering
policy and printing, which is `deploy.rs`'s established shape.

### Spec

- *"The builder image is pinned by digest and builds the static binary for the requested target."* — **Partial.** Bases
  are pinned and `--target` reaches the container, but the toolchain pin is defeated (P1 above). The real arm measures
  only this machine's triple; the ADR's "What this does not measure" discloses the aarch64 gap, and arm 1's run 4
  covers the refusal.
- *"No `build.rs`, proc macro or toolchain step runs host-side; the host only orchestrates Docker."* — **Met.**
  `cargo`/`rustc` stand-ins that record and fail (verify.sh:10983-10993) are a real assertion, not a hope;
  `builder::tag` runs only `git`.
- *"The output binary and its SHA-256 are placed where `holosmith upgrade` expects them."* — **Met**,
  `releases/<tag>/holosmith` + `holosmith.sha256` in `sha256sum -c` format. **P2:** `builder::place`'s
  `Placement::Current` arm (`src/builder.rs`, `place`) removes the pending file and returns success without writing
  `DIGEST`. A directory that holds the right bytes but no `.sha256` — including one left by the very error path three
  lines above, where the rename succeeded and the digest write failed — makes the command print `is already this
  build`, exit 0, and never produce the second file the bullet names. Smallest fix: on `Current`, write `DIGEST` when
  it is absent.
- *"Build failures surface the container's log tail rather than a generic error."* — **Met.** `builder::run` returns
  the last `TAIL_LINES` (40) of the captured file; `commands::build::run` prints it to stderr and exits 1.
- *"The diff review (HS-058) is documented as the real gate; this story only makes the build safe, not trusted."* —
  **Met**, verbatim in ADR-0080, `docs/build.md`, `GLOSSARY.md` and `src/builder.rs`'s header.

Scope creep: `holosmith build` is a third phase-4 verb the spec's CLI-by-phase table does not list — recorded in
ADR-0080 D1, disclosed, acceptable.

Gate-case check: `case_build` fails on deletion (run 1's command fails, so `case_build` never prints `ok`), and every
assertion I traced fires only on the feature misbehaving — ELF refusal (run 4), overwrite refusal (run 3), `:ro`

Standards: 5 findings, worst P1 (unnamed rust stage defeats the pin). Spec: 1 finding, worst P2 (missing `.sha256` on

## Resolution

Two defects the fix itself surfaced, both now recorded in `docs/notes.md` and ADR-0080 D2:

- **an `ENV` at the end of a Dockerfile is an environment no earlier `RUN` sees.** With node as the final stage,
  `RUN rustup target add …` exited 127 — the recipe had only ever worked because the final stage *was* the rust image,
  which is finding 1. The toolchain's `PATH` is now set immediately after the `COPY`s.
- **a copied `CARGO_HOME` is root-owned and the build runs as the operator's uid.** `failed to create directory
  /usr/local/cargo/registry/cache/…` (exit 101, after eight minutes). `CARGO_HOME` is unset in the recipe, so cargo
  uses `$HOME/.cargo` under `/build`, which the entry script creates.

After the fixes: `cargo test` **1319** in 64 binaries (597 lib + 11 `tests/build.rs` + the rest), `cargo fmt --check`
and `cargo clippy --all-targets -- -D warnings` clean, and the gate green — the numbers are in the ship comment.
